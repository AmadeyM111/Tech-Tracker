# Термины домена

Единый словарь: эти имена используются в коде, API и интерфейсе.
Код — на английском, интерфейс — на русском.

| Русский | English (код) | Значение |
|---|---|---|
| Рабочее пространство | workspace | Верхний контейнер: команда или подразделение. Граница данных и прав |
| Проект | project | Набор связанных задач с общей целью. Срока нет; статус — активный или архивный (ADR-0005) |
| Задача | task | Единица работы: исполнитель, статус, срок |
| Доска | board | Канбан-представление задач проекта |
| Колонка | column | Колонка доски, соответствует одному статусу задачи; колонки не настраиваются (spec 001, FR-28). Не путать со стадией воронки |
| Клиент | account | Компания-контрагент |
| Контакт | contact | Человек на стороне клиента |
| Сделка | deal | Потенциальная продажа: сумма, валюта, стадия |
| Стадия воронки | stage | Этап сделки в воронке |
| Воронка | pipeline | Упорядоченный набор стадий |
| Статус задачи | task status | Один из фиксированного набора: «К выполнению» (todo), «В работе» (in_progress), «На проверке» (review), «Готово» (done). Закрытая задача — в статусе «Готово». Колонки доски соответствуют статусам |
| Техадминистратор | tech admin | Роль: системные настройки, учётные записи, роли, журнал аудита. Доступа к бизнес-данным нет. Таких пользователей может быть несколько; роль ТА назначает любой активный ТА (ADR-0013) |
| Бизнес-администратор | business admin | Роль: создание проектов; в любом проекте — название и описание, участники (включая себя), передача и замена владельца, удаление; задачи и комментарии — только в проектах, где участвует; CRM (ADR-0013, spec 002 §5.2) |
| Смешанная роль (СМ) | mixed | **Упразднена (ADR-0013, 2026-10-16)**; встречается только в старых записях журнала аудита («Смешанная роль»). Прежнее определение: Техадминистратор + бизнес-администратор (ТЗ §4, ADR-0003). При расхождении действует матрица ТЗ §4: например, удаляет любой проект, а не только свой. Задачи читает и меняет, любые комментарии удаляет в проектах, где участвует; своя задача в проекте для этого не нужна. Добавить себя может в любой проект. «СМ — в любом проекте» в правах на задачи читается как «в любом, где участвует» (ADR-0009) |
| Пользователь | user | Роль: свои задачи в проектах, где участвует; без доступа к CRM |
| Бизнес-пользователь | business user | Термин ТЗ §6 (п. 6, 7), не отдельная роль: = роль «Пользователь» (spec 001, OI-43) |
| Менеджер | manager | Термин ТЗ §6 (п. 8), не отдельная роль: бизнес-администратор (смешанная роль упразднена, ADR-0013) (spec 001, OI-41) |
| Своя задача | own task | Задача, которую сотрудник создал для себя: он и автор, и исполнитель. Менять исполнителя может только БА |
| Свой проект | own project | Для БА — проект, где он участник: в нём БА правит любые задачи (ADR-0013, spec 002 §5.3). Прежнее толкование (владелец ИЛИ неудалённая задача как автор или исполнитель, ADR-0009 п.2) для БА заменено. Удалить проект может любой БА (ADR-0013) |
| Метка | label | Общая для рабочего пространства пометка задачи: одна метка доступна во всех проектах. Создают, переименовывают и удаляют БА; «Пользователь» только назначает существующие метки на свои задачи. На задаче не больше 10 меток (spec 001, FR-18b) |
| Владелец проекта | project owner | Участник проекта, отвечающий за проект; изначально — создатель. Владение передаётся только участнику с ролью БА (spec 001, FR-14, FR-14a); заблокированного владельца или владельца без роли БА заменяет любой БА (ADR-0013) |
| Участник проекта | project member | Пользователь, добавленный в проект; только участник читает задачи, комментарии, вложения и ленту проекта (spec 001, FR-15, FR-17) |
| Архивный проект | archived project | Проект в статусе «Архивный»: доступен только на чтение, кроме разархивирования, удаления и передачи владения; изменения — 409 `project_archived` (ADR-0005, spec 001, FR-14b) |
| Без роли | no role | Состояние учётной записи после создания или снятия роли: разрешены только вход, выход и смена своего пароля (spec 001, FR-66) |
| ИИ-агент (агент) | AI agent | Внешняя программа на базе языковой модели (например, Claude Code), которая работает с трекером через API, а не через браузер. В составе трекера модели нет (spec 007, ADR-0020) |
| Учётная запись агента | agent account (`is_agent`) | Учётная запись рабочего пространства с признаком «агент», под которой работает ИИ-агент. Создаёт только ТА; признак задаётся при создании и не меняется. Роль — «Пользователь», «Бизнес-админ» или «без роли» (не ТА). Пароля и входа в браузер нет, работает только по ключу доступа. В интерфейсе рядом с логином — метка «ИИ» (spec 007, FR-1, FR-2, FR-31) |
| Ключ доступа (ключ) | API key | Секрет учётной записи агента для запросов без пароля и cookie: заголовок `Authorization: Bearer <ключ>`, формат `gtk_` + 43 символа. Выпускает и отзывает только ТА; секрет показывается один раз, в БД хранится только SHA-256. Срок по умолчанию 90 суток, максимум 365; не больше 5 действующих ключей; 120 запросов в минуту; блокировка агента отзывает все его ключи (spec 007, FR-5…FR-16, FR-33; ADR-0020) |
| Операции агента | agent operations | Закрытый перечень из 10 действий, доступных по ключу: кто я, свои проекты, мои задачи, задачи проекта, карточка задачи, создание задачи и подзадачи, изменение задачи и смена статуса, чтение и добавление комментариев. Всё остальное по ключу — 403 (spec 007, FR-17…FR-27) |
| Инструменты агента | agent tools | Операции агента, оформленные для подключения по MCP: 11 инструментов (`whoami` … `add_comment`) локального процесса `backend/app/agent_mcp.py` (spec 007, FR-35; инструкция — `docs/agents.md`) |
| MCP | Model Context Protocol | Протокол, по которому ИИ-агент (Claude Code) подключает внешние инструменты. В трекере — локальный процесс на машине агента, транспорт stdio; точки MCP в сервере трекера нет (spec 007, раздел 3.7; ADR-0020) |
| Метка «ИИ» | agent mark | Пометка рядом с логином учётной записи агента в карточке задачи, комментариях, на доске, в списках задач и в «Учётных записях»; у людей метки нет (spec 007, FR-31) |
| Оператор | operator | Человек с доступом к серверу и `docker compose`; выполняет CLI-команды вне ролей: экспорт, импорт, демо-данные, обслуживание, резервную копию, восстановление CRM-объектов (ADR-0010). Не роль системы |
| Корзина | trash | Мягко удалённые объекты, 30 дней доступные для восстановления; показывает только то, что пользователь вправе восстановить (ADR-0010, spec 001, FR-25a) |
| История сделки | deal history | Изменения полей одной сделки: автор, время, поле, старое и новое значение; читают роли с правом «CRM: чтение» (spec 001, FR-35) |
| Лента активности | activity feed | События проекта (для участников) или сделки (для ролей с CRM): что произошло, кто и когда (spec 001, FR-38) |
| Журнал аудита | audit log | Только дописываемый журнал действий с учётными записями, ролями, сессиями, стадиями, сделками, владением и архивом проекта; по бизнес-сущностям — только метаданные; читает ТА (ADR-0006, spec 001, FR-41); записи о бывших СМ (`mixed`) показываются как «Смешанная роль»; обновление `0006` пишет записи от «системы» (ADR-0013) |
| Упоминание | mention | `@логин` участника проекта в комментарии; создаёт уведомление внутри приложения (ADR-0008, spec 001, FR-71) |
| R1 / MVP / пилот | R1 / MVP / pilot | Синонимы: один и тот же объём — ТЗ §2 (`docs/brief/vision.md`). `docs/mvp.md` — черновик и при расхождении уступает ТЗ и spec (spec 001, OI-44, ADR-0008) |
| Цель | objective | Цель команды (бэклог) |
| Ключевой результат | key result | Измеримый результат цели (бэклог) |
