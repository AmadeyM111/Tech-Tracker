# Метрики пилота (к контрольной точке 2026-11-23)

Только чтение, без новой схемы (спека 031). Персональных данных в отчёте нет: счётчики, медианы и названия клиентов агентов.

## Как снять отчёт
На сервере (запуск делает оператор; метрики читают БД и ничего в неё не пишут — транзакция `READ ONLY`):

```bash
docker exec <проект>-api-1 gtrack pilot-report --from 2026-11-09 --to 2026-11-23 > pilot-2026-11-23.md
docker exec <проект>-api-1 gtrack pilot-report                # последние 14 суток
docker exec <проект>-api-1 gtrack pilot-report --active-days 14   # окно «активных» — 14 суток
```

`--from` включается, `--to` нет; даты — по Москве. Вывод — Markdown, готов к вставке в `docs/pilot/report-template.md` (раздел «Выводы» заполняет человек).

## Определения
| Метрика | Как считается |
|---|---|
| Пользователей с ролью | `workspace_member.role` не `NULL`, пользователь не заблокирован |
| Активных за N дней | различные пользователи с событием в журнале (`domain_event.actor_id`), сессией (`user_session.last_activity_at`), токеном `gtrk_` (`api_token.last_used_at`) или облачным клиентом (`oauth_grant.last_used_at`) за N суток до конца периода. Просроченные сессии удаляет `gtrack maintenance`, поэтому основной источник — журнал |
| Зарегистрировано за период | `app_user.created_at` в периоде; «самостоятельных регистраций» — `self_registered` за всё время |
| Задач создано | `task.created_at` в периоде (включая подзадачи) |
| Задач закрыто | различные задачи с событием `task.updated`, где `status` стал `done`, в периоде |
| Просрочено сейчас | живые задачи не в `done` со сроком раньше даты конца периода (МСК) |
| Время до первой реакции | для новых задач верхнего уровня: от создания до первого комментария или изменения задачи от другого пользователя (не автора); считается медиана и 90-й процентиль среди задач с реакцией; доля задач с реакцией |
| Токены `gtrk_` | выпущено за период; активных сейчас (не отозваны, не истекли); пользователей с активным токеном и применявших токен за период |
| Облачные клиенты | `oauth_grant`: подключено за период, активных сейчас, пользователей, чей клиент работал за период |
| Действия агентов | события журнала с `client_name` (и `gtrk_`, и OAuth) за период; топ-5 клиентов |
| Вложения | загружено за период (не удалённых), число задач с вложениями, суммарный объём |
| Упоминания | строки `comment_mention` за период и число упомянутых пользователей |
| Уведомления | создано за период, из них прочитано (`read_at`) |

## Ограничения
- «Закрыто» берётся из журнала: переходы, сделанные до появления события `task.updated` с изменением статуса, не видны (на пилоте журнал полный с R1.1).
- Журнал пишет клиента (`client_name`) только для MCP; действия веб-интерфейса в «агентах» не учитываются.
- Метрики показывают активность, а не качество: выводы — в разделе «Выводы» отчёта.
