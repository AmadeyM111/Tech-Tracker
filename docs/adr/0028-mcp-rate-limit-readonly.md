# ADR-0028. Лимит частоты MCP и токен только на чтение

- **Дата:** 2026-11-15
- **Статус:** предложено (спека 032)

## Решение
На `/mcp` каждый `tools/call` считается в памяти процесса по `token_id` (строка `api_token` или OAuth access). Лимит — 120 в минуту; превышение — HTTP 429 `rate_limited` и `Retry-After`. `initialize` и `tools/list` в счёт не входят.

Персональный `gtrk_` может быть `api_token.read_only`. OAuth scope `mcp:read` без `mcp` даёт то же. Пишущие инструменты скрываются в `tools/list` и отвечают `forbidden` при вызове. Старые токены и гранты со scope `mcp` остаются с записью.

## Причины
- Публичный MCP без тормоза разгоняет скомпрометированный ключ.
- Наблюдателю (152-ФЗ, чужой агент) нужен доступ без записи, без отдельной учётки агента.

## Альтернативы и почему отвергнуты
- **Redis / общий счётчик.** Отвергнуто: один воркер API на пилоте (YAGNI).
- **Лимит на все методы, включая `initialize`.** Отвергнуто: клиент иначе не сможет переподключиться после 429.
- **Короткий ключ задачи / учётка агента (спека 022).** Вне рамок 032.

## Последствия
- Миграция `0018` аддитивна; выкатка с `ALLOW_MIGRATIONS=1`.
- Несколько процессов API считают лимит раздельно.
