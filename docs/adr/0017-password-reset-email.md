# ADR-0017. Самостоятельный сброс пароля по email

- **Дата:** 2026-11-04
- **Статус:** принято (владелец, 2026-11-04)
- **Связано:** ADR-0004 (пароли и сессии: «Самостоятельного сброса (по email) в R1 нет»), ADR-0006 (аудит),
  ADR-0010 (экспорт и импорт), `specs/007-password-reset-email/spec.md`

## Решение
Для R1 добавляется самостоятельный сброс пароля с экрана входа. Пользователь указывает email, получает письмо
со ссылкой на одноразовый токен (срок 30 минут) и задаёт новый пароль. Отправка идёт через SMTP-сервер, который
настраивает оператор переменными окружения; внешних почтовых API нет. Без настроенного SMTP функция выключена.
Сброс через технического администратора сохраняется как прежде.

Этим ADR отменяется ограничение ADR-0004 «самостоятельного сброса по email в R1 нет». Остальные решения ADR-0004
(правила пароля, сессии, защита от перебора) не меняются.

## Причины
- Администратор — узкое место: пользователь ждёт, пока кто-то выдаст пароль.
- SMTP внутри стенда не требует интернета; ТЗ §5 (работа без интернета) сохраняется.
- Токен хранится хешем, одноразовый, с коротким сроком; все сессии пользователя завершаются при успехе. Это
  сохраняет модель отзыва сессий из ADR-0004.
- Ответ на запрос одинаков для существующего и несуществующего email, поэтому сброс не раскрывает список учётных записей.

## Альтернативы и почему отвергнуты
- **Внешний почтовый сервис (SendGrid, Mailgun и т. п.)** — внешний вызов без решения в ADR запрещён (AGENTS.md);
  данные пользователей уходят третьей стороне.
- **Сброс по логину без email** — токен не к кому привязать: доставки нет, ответ раскрывал бы существование логина.
- **Код в ответе на запрос (без почты)** — то же, что выдача пароля без проверки владельца учётной записи.
- **Запрос администратору с экрана входа (без email)** — владелец выбрал сброс по email. Вариант остаётся доступен, если решение изменится.
- **Только администратор (статус quo)** — не отвечает на запрос владельца о самостоятельном сбросе.

## Последствия
- Новая колонка `users.email` (уникальна среди активных, без учёта регистра) и таблица `password_reset_tokens`
  (хеш токена, срок, признак использования). Миграция Alembic; применённые миграции не правятся.
- Новые переменные окружения `SMTP_*`; `.env.example` и `deploy/` дополняются. Новых Python-зависимостей нет
  (`smtplib`); если понадобится библиотека — решение в `plan.md`.
- Экспорт и импорт (ADR-0010): `email` в файл экспорта не включается; импорт его не заполняет.
- Журнал аудита получает события `password_reset_requested` и `password_reset_completed` без персональных значений (ADR-0006).
- Риск: ссылка в письме может быть перехвачена при доставке. Снижается сроком 30 минут, одноразовостью и тем,
  что после сброса все сессии завершаются. Для локального стенда риск принимается при утверждении этого ADR.
- ADR-0004 в части «самостоятельного сброса по email в R1» заменён этим ADR; остальные его решения действуют.
