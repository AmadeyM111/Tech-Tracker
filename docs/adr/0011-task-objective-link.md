# ADR-0011. Связь задача → цель: не закладывается, добавляется аддитивной миграцией

- **Дата:** 2026-10-13
- **Статус:** принято
- **Связано:** уточняет ADR-0002 (раздел «Последствия»); ТЗ §2 (цели — вне рамок);
  `specs/001-pilot-r1/spec.md` (OI-2, OI-101, Data Model);
  `specs/001-pilot-r1/consensus-2026-10-13.md` (OI-2, решение аналитика и архитектора);
  `docs/open-questions.md` (вопрос 3)

## Решение
В модели данных R1 нет поля или связи «задача → цель». Когда цели (OKR) появятся, связь
добавляется аддитивной миграцией: новая таблица или новое необязательное поле, без
изменения и переноса существующих данных. Объём R1 решение не меняет. Требование ADR-0002
«предусмотреть связь "задача → цель" на уровне модели данных» читается так: модель задач и
проектов не должна мешать такой миграции.

## Причины
- Цели в R1 вне рамок (ТЗ §2), сущности цели нет. Поле, которое ссылается на
  несуществующую сущность, не проверяется ни одним сценарием и ни одним тестом.
- Добавить необязательную связь к существующей таблице можно аддитивной миграцией без
  переписывания модели. Это и было целью ADR-0002.
- По C-6 spec принятые решения меняются только через ADR. ADR-0002 не редактируется, поэтому
  уточнение оформлено отдельным ADR.

## Альтернативы и почему отвергнуты
- **Необязательное поле `objective_id` в R1:** ссылается на несуществующую сущность,
  усложняет экспорт, импорт и миграции, ничего не проверяет.
- **Заготовка таблицы целей в R1:** это частичная реализация OKR, а она вне рамок ТЗ §2.

## Последствия
- В `plan.md` записывается, что связь «задача → цель» добавляется позже аддитивной
  миграцией.
- Формат экспорта (ADR-0010) версионирован, поэтому появление связи меняет версию схемы.
- ADR-0002 остаётся в силе в остальной части.
