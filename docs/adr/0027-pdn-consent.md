# ADR-0027. Согласие на обработку ПДн: хранение факта и версии, гейт для существующих пользователей

- **Дата:** 2026-11-15
- **Статус:** принято (спека 021 v2, решения владельца 2026-11-15)

## Решение
Согласие хранится в `app_user` (`pdn_consent_version`, `pdn_consented_at`) и в `registration_request` до подтверждения email.
Версия — дата текста, одна на Политику и Согласие. Тексты — файлы данных в репозитории, реквизиты оператора — один файл.
Доступ без согласия закрывает гейт `get_active_actor` (403 `pdn_consent_pending`) по образцу гейта одноразового пароля.
Функция за флагом `PDN_CONSENT_ENABLED`; в `production` флаг не включается при наличии `[ЗАПОЛНИТЬ]` (приложение не стартует).

## Причины
- Факт и версия в самой записи пользователя проще отдельной таблицы историй и нужны только для проверки «согласие текущей версии».
- Гейт в одном месте закрывает и существующих пользователей, и учётные записи, созданные через провайдеров, и токены агентов не затрагивает.
- Тексты вне вёрстки позволяют юристу менять их без правки фронта; версия по дате даёт повторное подтверждение при каждом изменении.

## Альтернативы и почему отвергнуты
- **Таблица `pdn_consent` с историей версий.** Отвергнуто: избыточно (YAGNI); история событий — в `domain_event` (`user.pdn_consent_given`).
- **Тексты в вёрстке фронта.** Отвергнуто решением владельца.
- **Только флажок на форме без гейта.** Отвергнуто: существующие пользователи остались бы без согласия.

## Последствия
- Миграция `0017` останавливает автодеплой: ручная выкатка (`ALLOW_MIGRATIONS=1`).
- Отзыв согласия вне кода: по обращению на `support@leggent.ru`, вручную (спека 021, §6).
- Гейт `pdn_consent_pending` — новый код 403; фронт ведёт на `/pdn-consent`.
