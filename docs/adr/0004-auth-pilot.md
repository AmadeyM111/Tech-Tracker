# ADR-0004. Пароли и сессии пилота

- **Дата:** 2026-10-13
- **Статус:** принято
- **Связано:** ТЗ §3, `specs/001-pilot-r1/spec.md` (OI-39, OI-49, OI-51, FR-2, FR-5, FR-6, FR-52…FR-65, AC-20, AC-23, AC-27…AC-45),
  ADR-0003
- **Обновление 2026-10-13:** OI-5 закрыт: блокировка завершает все сессии пользователя
  (spec FR-5, AC-20), ответ на вход заблокированного совпадает с ответом на неверный пароль
  (OI-88). Права СМ на переназначение задач заблокированного — в проектах, где участвует
  (ADR-0009); последний администратор не может заблокировать себя (ADR-0009). Файл пароля
  первого ТА удаляется и при импорте (ADR-0010).
- **Обновление 2026-10-13:** одноразовый пароль задаёт администратор, генерирует клиент;
  сервер его не возвращает (spec OI-108).

## Решение

**Пароли**
- Минимум 12 символов. Правил на состав (цифры, спецсимволы) нет.
- Пароль, совпадающий с одним из 10 000 самых частых паролей, при установке отклоняется.
- Принудительной смены пароля по расписанию нет.
- Хеш — Argon2id через `argon2-cffi`. Параметры подбираются так, чтобы хеширование занимало
  100–500 мс на целевом стенде (3 vCPU, 6 ГБ RAM), и фиксируются в конфигурации.
- Техадминистратор создаёт учётную запись с одноразовым паролем; при первом входе система
  требует задать новый.
- Пароль ни в каком виде не попадает в логи, трассировки ошибок и ответы API.
- Смена пароля завершает все остальные сессии пользователя.
- Забытый пароль сбрасывает техадминистратор или смешанная роль: выдаётся новый одноразовый
  пароль, все сессии пользователя завершаются. Самостоятельного сброса (по email) в R1 нет.

**Сессии**
- Серверная сессия; идентификатор — в cookie с флагами `HttpOnly`, `SameSite=Lax`, `Secure`.
  В локальной разработке по http флаг `Secure` отключается переменной окружения.
- Сессия истекает после 8 часов без активности и не позднее 7 суток с момента входа;
  после этого нужен повторный вход.
- Выход удаляет сессию на сервере.
- Техадминистратор (и смешанная роль, ADR-0003) может завершить все сессии пользователя и
  заблокировать учётную запись. Блокировка сама завершает все сессии пользователя.

**Транспорт** (принцип заказчика — «максимально безопасно»)
- Поставляемая конфигурация принимает подключения только по HTTPS, TLS 1.2 и выше; http
  перенаправляется на HTTPS. Оператор подключает свой сертификат; если его нет, при первом
  запуске генерируется самоподписанный. Отключать `Secure` можно только в локальной
  разработке вне поставляемой конфигурации.

**Первый техадминистратор**
- Сгенерированный пароль пишется в файл в томе данных с правами на чтение только для
  владельца и удаляется после первой смены пароля. В логи он не попадает: запрет на пароли в
  логах действует без исключений.

**Демо-пользователи**
- Команда загрузки демо-данных создаёт каждому уникальный случайный одноразовый пароль и
  пишет их в такой же файл, доступный только оператору. Известных демо-паролей в
  репозитории нет: демо-стенд не должен открываться паролем из открытого исходного кода.

**Защита от перебора**
- После 5 неудачных попыток подряд вход по логину отклоняется в течение 15 минут, в том
  числе с верным паролем. Ответ при этом идентичен ответу на неверный пароль, чтобы не
  раскрывать факт блокировки.
- Ответы на несуществующий логин и на неверный пароль совпадают по коду и телу.

## Причины
- Правила на состав пароля снижают стойкость на практике: люди обходят их шаблонами.
  Длина и отказ от частых паролей дают больше.
- Плановая смена пароля приводит к предсказуемым паролям; меняем только при необходимости.
- Серверная сессия выбрана вместо JWT: её можно отозвать мгновенно (смена пароля, выход,
  блокировка).
- Время хеширования 100–500 мс делает перебор дорогим и укладывается в норматив входа.
- Одинаковые ответы на несуществующий логин и неверный пароль не дают перебрать логины.

## Альтернативы и почему отвергнуты
- **JWT без серверного состояния** — нельзя мгновенно отозвать сессию.
- **Правила на состав и плановая смена пароля** — см. «Причины».

## Последствия
- Новая зависимость `argon2-cffi`; её нужно обосновать в `plan.md` (лицензия MIT,
  совместима с Apache 2.0 — проверить при добавлении).
- Список 10 000 частых паролей поставляется в репозитории: после сборки образов система
  работает без интернета (ТЗ §5). Источник и лицензию списка нужно выбрать в `plan.md`.
- Нужна серверная таблица сессий и отзыв всех сессий пользователя (смена пароля, а также
  блокировка — после решения OI-5 в spec).
- Блокировка входа по логину позволяет постороннему временно не пускать конкретного
  пользователя, подбирая его пароль. Для localhost-пилота риск принимается.
- Самоподписанный сертификат вызывает предупреждение браузера; инструкция в README должна
  это объяснять.
- Команды разработки из `AGENTS.md` работают по http; для них `Secure` отключается
  настройкой окружения.
