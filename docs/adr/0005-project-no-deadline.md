# ADR-0005. У проекта нет срока, есть статус

- **Дата:** 2026-10-13
- **Статус:** принято
- **Связано:** ТЗ §2, `docs/glossary.md`, `specs/001-pilot-r1/spec.md` (OI-3, OI-60,
  FR-14, FR-14b)
- **Обновление 2026-10-13:** OI-60 закрыт (заказчик, З-4): архивирует и разархивирует
  владелец или СМ (в любом проекте, ADR-0009); архивный проект доступен только на чтение,
  кроме разархивирования, удаления и передачи владения, прочее — 409 `project_archived`;
  по умолчанию скрыт из списков (spec FR-14b, AC-70, AC-71). Окончательное удаление
  проекта через 30 дней после мягкого — ADR-0010. OI-61 закрыт: утерянные решения получены
  заново.

## Решение
У проекта нет поля срока. Вместо срока у проекта есть статус: «активный» или «архивный».
Новый проект создаётся активным. Определение в глоссарии меняется с «набор задач с целью
и сроком» на «набор связанных задач с общей целью».

## Причины
- ТЗ §2 перечисляет поля проекта (название, описание, участники, владелец) без срока;
  расхождение было только в глоссарии.
- Сроки задаются на уровне задач; срок проекта без зависимостей задач и диаграммы Ганта
  (вне рамок, ТЗ §2) ничего не проверяет.
- Статус позволяет убирать завершённые проекты из работы, не удаляя их.

## Альтернативы и почему отвергнуты
- **Добавить срок проекта** — расширяет объём ТЗ без сценария, который его использует.

## Последствия
- Модель данных проекта: поле статуса, без поля срока.
- Поведение архивного проекта (кто архивирует, можно ли менять задачи, виден ли в списках)
  не определено — spec OI-60.
- Решение заказчика по OI-3 передано с обрывом текста (spec OI-61); если в утерянной части
  были дополнительные условия, ADR дополняется.
