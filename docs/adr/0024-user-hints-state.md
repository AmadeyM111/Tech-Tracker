# ADR-0024. Состояние закрытых подсказок интерфейса хранится на сервере, у пользователя

- **Дата:** 2026-11-10
- **Статус:** предложено (черновик для спеки 026; принимает владелец при запуске R3)

## Решение
Закрытие подсказки (первая — «Подключить ИИ-агента к GTrack», ключ `ai_agent`) хранится в таблице
`user_hint_dismissal (user_id, hint_key, dismissed_at)` и отдаётся клиенту полем `dismissed_hints` в `GET /me`. Закрытие и возврат —
`POST` и `DELETE /api/v1/me/hints/{key}/dismiss` (204, идемпотентно). Допустимые ключи — белый список в коде; неизвестный ключ — 404.
События в журнал аудита не пишутся: это настройка интерфейса, а не бизнес-данные.

## Причины
ТЗ (T-13 F5) требует хранить состояние «в профиле»; браузерное хранилище не переживает смену устройства или очистку и возвращает
подсказку. Таблица вместо столбца позволяет добавлять следующие подсказки без миграций. Поле в `GET /me` не добавляет запроса и
исключает мигание карточки при загрузке.

## Альтернативы и почему отвергнуты
- `localStorage` — без миграции, но состояние не следует за пользователем и сбрасывается.
- Столбец `app_user.hints text[]` — каждое расширение хранения меняет таблицу пользователей; хуже для откатов.
- Отдельный `GET /me/hints` — лишний запрос и мерцание.

## Последствия
Аддитивная миграция (откат — `drop table`); расширение `MeResponse` (аддитивно); таблица попадает в `gtrack export` и копию БД автоматически
(копия — дамп; экспорт — по реестру таблиц `domain/registry.py`, там её нужно учесть).
