# ADR-0026. Внешние провайдеры входа и правила привязки учётных записей

- **Дата:** 2026-11-13
- **Статус:** принято (спека 029, APPROVED 2026-11-14)

## Решение
Вход через Яндекс ID, VK ID и Google — только как OAuth 2.0 / OpenID Connect клиент с PKCE. Ключ идентичности — стабильный идентификатор провайдера, не email. Автопривязка существующей учётки по email допускается только при подтверждении email провайдером (сейчас — только Google). Учётка, созданная через провайдера, — роль «Пользователь», без пароля. Отвязка запрещена, если нет другого способа входа.

## Причины
- У Яндекса и VK ID по официальной документации нет признака подтверждения email; автопривязка по нему открыла бы захват учёток.
- Email у провайдера может смениться; стабильный идентификатор этого не боится.
- Провайдерские токены не нужны для входа; их хранение увеличивает риск без пользы.

## Альтернативы и почему отвергнуты
- **Автопривязка по email для всех провайдеров.** Отвергнуто: см. причины.
- **Хранить access и refresh токены провайдера.** Отвергнуто: не нужны для входа; риск утечки.
- **Ключ — email.** Отвергнуто: email меняется у провайдера.
- **Единственный способ входа без пароля (только магическая ссылка).** Отвергнуто: провайдеры сокращают ввод и снимают зависимость от почты.

## Последствия
- `app_user.password_hash` становится nullable; все пути, читающие хэш, обрабатывают `NULL`.
- Миграция `0016` (см. спеку 029 раздел 7; `0015` — «Запомнить меня»): `external_identity`, `oauth_login_state`, `magic_link_token`, колонки `session.auth_method` и `session.remember`.
- Яндекс ID и VK ID входят в первую поставку за флагами; Google — за флагом до юридической оценки 152-ФЗ.
- Решения по Q-1…Q-10 приняты владельцем 2026-11-14 (все рекомендации спеки).
