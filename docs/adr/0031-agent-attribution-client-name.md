# ADR-0031. Атрибуция агента по `client_name`, без `is_agent`

- **Дата:** 2026-11-16
- **Статус:** предложено (спека 022 срез CD-05, спека 035)

## Решение
В карточке, списке и на доске агент отличается от человека по
`domain_event.client_name` последнего события задачи (и последнего назначения
исполнителя). Поля API: `last_client_name`, `assignee_client_name`. Колонки
`app_user.is_agent` и `task.*agent*` в этом срезе нет.

Черновик сущностей — MCP `propose_entities`: без `commit=true` записей в БД нет.

## Причины
- Имя токена / OAuth-клиента уже пишется в журнал (ADR-0018).
- `is_agent` столкнулся бы с миграциями 0019/0020 соседних сессий.
- Ручная разметка сущностей — боль кастдева; запись только по явному commit.

## Альтернативы и почему отвергнуты
- **`app_user.is_agent`.** Отвергнуто в этом срезе: отдельная учётка — следующий
  шаг спеки 022, не этот PR.
- **Колонка на `task`.** Отвергнуто: дублирует журнал, расходится при правке в вебе.
- **LLM на сервере для разбора.** Отвергнуто: детерминированный формат текста.

## Последствия
- Чтение атрибуции — пакетный запрос к `domain_event` по id страницы (не N+1).
- Инцидент при commit = задача + комментарий «блокер», пока нет поля `blocked`.
