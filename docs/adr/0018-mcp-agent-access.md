# ADR-0018. Доступ AI-агентов через MCP: персональные токены, локальные клиенты в R1

- **Дата:** 2026-11-07
- **Статус:** принято; частично пересмотрен ADR-0025 (2026-11-12): OAuth для облачных клиентов — см. там; п. 1–4, 6–7 в силе
- **Связано:** `specs/020-mcp-ai-native/spec.md`; ТЗ §2 (вне рамок, каналы с внешним адресом),
  §4 (роли); ADR-0004 (сессии — не меняется; токены добавляются рядом), ADR-0006 (аудит),
  ADR-0010 (экспорт), ADR-0012.

## Решение
1. **Аутентификация агентов — персональные токены доступа (PAT).** Токен выдаёт сам пользователь
   в веб-интерфейсе. Права токена равны правам владельца. Токен имеет имя, срок жизни 90 дней и
   отзывается вручную. У пользователя не больше 10 активных токенов. Токен показывается один
   раз; в БД хранится SHA-256 от токена (256 бит случайности, поэтому быстрый хеш достаточен).
2. **Токен работает только на MCP-эндпоинте** (`/mcp`). В REST API `/api/v1` он не принимается,
   а управлять токенами токеном нельзя: маршруты `/api/v1/me/tokens` принимают только cookie-сессию.
3. **Блокировка учётной записи отзывает все её токены** (как сессии, ADR-0004). Выдача и отзыв
   токена пишутся в журнал аудита как действия с учётной записью (ADR-0006).
4. **Транспорт MCP — два варианта поверх одного API:**
   - HTTP Streamable на `/mcp` для клиентов, которые подключаются по URL на localhost;
   - команда `gtrack mcp` (stdio) для локальных агентов, которые запускают процесс. Команда
     только пересылает вызовы на `/mcp` с токеном; бизнес-логики в ней нет.
5. **Облачные клиенты (ChatGPT и подобные) в R1 не поддерживаются.** Для них нужен публичный
   HTTPS-адрес, а ТЗ §2 и AGENTS.md исключают внешние адреса в пилоте. Поддержка потребует
   отдельного ADR, который явно изменит это правило и разберёт безопасность.
6. **Атрибуция в ленте.** Событие ленты проекта получает поле клиента с именем токена (до 64
   символов, как текст пользователя, без разметки). Например: «Иван через «Claude Code на
   ноутбуке».
7. **Инструменты MCP в R1:** чтение и запись задач, подзадач, проектов (чтение) и комментариев.
   Участники, владение, удаление, роли, учётные записи и CRM через MCP не открываются.

## Причины
- Локальные агенты (Claude Code, Codex CLI, Cursor) работают на той же машине, что и пилот,
  поэтому внешних вызовов нет, и требования ТЗ по localhost выполняются.
- Персональный токен с правами владельца не вводит новой модели прав: проверки остаются в
  доменных сервисах, как и для веб-интерфейса (ТЗ §4, AGENTS.md «Права»).
- Отзыв по блокировке закрывает риск «уволенный сотрудник с живым токеном».
- Пилот на localhost: OAuth-поток для MCP избыточен (YAGNI).

## Альтернативы и почему отвергнуты
- **OAuth 2.1 для MCP.** Требует сервера авторизации и потока подтверждения; в localhost-пилоте
  не окупается.
- **Переиспользовать cookie-сессию.** Агенты не умеют вести cookie-сессию и её CSRF-защиту;
  сессия истекает через 8 часов бездействия, что неудобно для фоновых агентов.
- **Публичный адрес для ChatGPT через туннель.** Конфликтует с ТЗ §2 и AGENTS.md; отложено.
- **Токен с доступом и к REST API.** Расширяет поверхность атаки без выгоды для MCP; отвергнуто.

## Последствия
- Миграция `0009`: таблица токенов и поле клиента в `domain_event` (аддитивно).
- Новый каталог событий: выдача и отзыв токена, оба — аудит.
- Новая зависимость `mcp` (официальный SDK, MIT). Обосновывается в `specs/020-mcp-ai-native/plan.md`.
- ADR-0004 не меняется: сессии остаются для веб-интерфейса.
