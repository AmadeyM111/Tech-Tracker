# ADR-0010. Хранение удалённого, экспорт и импорт

- **Дата:** 2026-10-13
- **Статус:** принято
- **Связано:** ТЗ §2, §3, §6 п.11; `AGENTS.md` («Удаление»); ADR-0006;
  `specs/001-pilot-r1/spec.md` (OI-12, OI-33, OI-59, OI-81, FR-25…FR-25c, FR-37, FR-40,
  BR-7, BR-11, NFR-10, AC-17, AC-63, AC-93, AC-101); `specs/001-pilot-r1/consensus-2026-10-13.md`
  (З-7, З-10); `docs/open-questions.md` (вопросы 8, 9)

## Решение
**Хранение удалённого (З-7).** Всё удаляется сначала мягко и 30 дней лежит в корзине.
Задачи, проекты, комментарии и вложения через 30 дней удаляются окончательно, вместе с
файлами вложений. Сделки, клиенты и контакты окончательно не удаляются никогда: через
30 дней они уходят из корзины, но остаются в БД. Восстановить их после этого может только
оператор отдельной командой. Кнопка окончательного удаления для них возвращает 422.

**Экспорт и импорт (З-10).** Экспорт и импорт выполняет оператор CLI-командой, вне ролей.
В выгрузку входит всё рабочее пространство: пользователи с хешами паролей, роли, доменные
сущности, журнал аудита, история сделок, лента активности, метаданные и файлы вложений.
Сессии не входят. Формат — архив из `data.json` и каталога `files/`. Файл выгрузки
доступен на чтение только владельцу, как файл пароля первого техадминистратора. Импорт
выполняется только в «пустую» систему, где есть лишь автоматически созданные данные
(первый техадминистратор, воронка по умолчанию). Импорт заменяет их, удаляет файл с
паролем первого техадминистратора и сохраняет идентификаторы. Импорт в непустую систему и
импорт выгрузки другой версии схемы отклоняются. «Без потерь» означает: цикл экспорт →
импорт → экспорт даёт идентичный `data.json` (метка времени экспорта не сравнивается) и те
же sha256 файлов вложений. Автотест проверяет команду, а не HTTP API.

## Причины
- Сделки, клиенты и контакты — история продаж, их потеря необратима. Задачи и прочее после
  30 дней в корзине ценности не несут, а файлы вложений занимают диск.
- `AGENTS.md` требовал «данные по сделкам и задачам не теряем». Для сделок правило
  сохраняется, для задач заказчик его ослабляет.
- Техадминистратор не имеет доступа к бизнес-данным (ТЗ §4), а у бизнес-ролей нет доступа
  к пользователям и аудиту. Полную выгрузку может сделать только оператор, вне ролей.
- Импорт только в пустую систему убирает конфликты идентификаторов и слияние.
- Сравнение по `data.json` и sha256 — проверяемый критерий «без потерь».

## Альтернативы и почему отвергнуты
- **Окончательно удалять всё, включая сделки:** теряется история продаж.
- **Не удалять ничего окончательно:** растут БД и том вложений, хотя задачи и файлы после
  корзины не нужны.
- **Экспорт через HTTP API под ролью:** ни у одной роли нет доступа ко всем данным, а
  отдельная роль ради экспорта меняет матрицу ТЗ §4.
- **Импорт со слиянием:** конфликты идентификаторов и связей, для пилота не нужно.
- **Экспорт без вложений (они в резервной копии):** тогда «без потерь» не проверяется
  одним архивом.

## Последствия
- Отступление от ТЗ §6 «каждый пункт покрывается автотестом на уровне API»: пункт 11
  проверяется автотестом команды (spec NFR-10).
- Нужны команды оператора: экспорт, импорт, восстановление сделки, клиента или контакта,
  ушедших из корзины. Пути и формат — в `plan.md`.
- В `data.json` нужна версия схемы, чтобы отклонять импорт другой версии.
- Файл выгрузки содержит хеши паролей и бизнес-данные; оператор хранит его как секрет.
- Правило об удалении в `AGENTS.md` приведено в соответствие с этим ADR.
