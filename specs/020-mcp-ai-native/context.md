# Контекст: AI Native через MCP (фича 020)

Дата обзора: 2026-11-07. Обзор сделан вручную по `AGENTS.md`, `CLAUDE.md`, `docs/STATE.md`,
`docs/brief/vision.md`, `docs/adr/`, `backend/app/api/`, `backend/app/domain/`.

## Что уже есть и что переиспользуем
- **API:** REST под `/api/v1` (FastAPI). Роутеры `projects`, `tasks` (`/projects/{id}/tasks`,
  `/me/tasks`, `/tasks*`), `boards`, `comments`, `me`, `users`, `audit`. Ошибки — `{"detail","code"}`.
- **Аутентификация:** только cookie-сессия (`app/domain/auth/sessions.py`, `app/api/deps.py`,
  `get_actor`). Проверка Origin для небезопасных методов. Токенов для программных клиентов нет.
- **Права:** `app/domain/access/roles.py` — роли и `Capability` (например `BUSINESS_ACCESS`,
  `TASK_ASSIGN_OTHERS`, `PROJECT_MANAGE_ANY`). Объектные права — в доменных сервисах
  (`app/domain/tasks/service.py`, `app/domain/projects/service.py`). Гейт роутера —
  `require_capability(...)`.
- **Бизнес-логика уже в сервисах**, роутеры тонкие (AGENTS.md: «Слои не смешиваются»). MCP-слой
  должен вызывать те же сервисы, а не дублировать правила.
- **Аудит и лента:** `app/domain/events` (аудит по ADR-0006 только для учётных записей,
  ролей, сделок, стадий, владения и архива); `app/domain/activity` — лента проекта.
- **CLI:** `gtrack` (`app/cli/main.py`) — есть место для команды запуска локального MCP-сервера.

## Чего нет
- Пакета `mcp` (Python SDK) в `backend/pyproject.toml` и в `.venv` нет. Добавление = новая
  зависимость, её нужно обосновать в `plan.md` (AGENTS.md, «Принципы разработки»).
- Модели API-токена, таблицы под токены, миграции для них.
- CRM не реализована (R1.3 не начат, ADR-0012): инструментов CRM в MCP пока быть не может.

## Конфликты с принятыми документами (нужны решения до плана)
1. **ChatGPT и облачные клиенты** подключают удалённые MCP-серверы только по публичному HTTPS-адресу.
   ТЗ `docs/brief/vision.md` §2 исключает каналы, которым нужен внешний адрес («несовместимо с
   localhost-пилотом»); AGENTS.md запрещает внешние вызовы без ADR. Для Claude Code, Codex CLI,
   Cursor и подобных клиентов, которые запускаются на той же машине, конфликта нет.
2. **Токены для программного доступа** — новый механизм аутентификации. ADR-0004 описывает только
   сессии. Нужен ADR.
3. **Аудит действий агента.** ADR-0006 не требует аудита задач, но нужна понятная атрибуция
   («кто сделал через какой клиент») в ленте.
