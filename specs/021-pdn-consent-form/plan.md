# Plan: согласие на обработку ПДн при регистрации (spec 021, минимальный объём)

- **Статус:** ОТЛОЖЕНО (2026-11-08). Не начинать: spec 021 припаркована владельцем, обновление spec 019 не начато.
  Предложения из spec §8 не подтверждены.
  Версия spec 019 с формой согласия тоже нужна до начала (ADR-0019).
- **Ветка:** dev (`feature/021-pdn-consent-form`). Мерж в main и выкатка на прод — только с отдельного одобрения владельца.

## 1. Что меняется по сравнению с первой версией
- Таблица `personal_data` не нужна: ФИО и email уже в учётной записи (spec 019).
- Экспорт PDF/docx не делаем (Q5).
- Согласие собирается в форме регистрации, поэтому меняется spec 019, а не только новая фича.
- Шифрование полей не делаем (Q8, предложение): поля совпадают с уже хранимыми.

## 2. Архитектура
Слои по AGENTS.md: роутер → схема → один вызов сервиса `domain/` → схема ответа. Ошибки — `AppError`.

- **Миграция (новая, после текущей головы):**
  - `consent_texts`: `id`, `version` (уникальна), `body`, `operator_block` (ИП, ИНН, адрес, ответственный — из Q2),
    `effective_from`, `created_at`.
  - `user_consents`: `id`, `user_id`, `consent_text_id`, `given_at`, `withdrawn_at` (nullable). Частичный уникальный
    индекс по `user_id` `WHERE withdrawn_at IS NULL`.
- **Сервис `consent/`:** `current_text()`, `record_consent(user_id, version)` (вызывается при подтверждении email
  в регистрации), `withdraw(user_id)`, `status_for_admin(user_id)` (только факт, версия, даты).
- **Регистрация (spec 019):** на странице регистрации — текст согласия и отметка, обязательная. Сервер проверяет версию
  и отметку в запросе `POST /auth/register` и сохраняет согласие при подтверждении. Без отметки — 422.
- **Эндпоинты:**
  - `GET /consent/current` — текст и блок оператора (публично, для формы регистрации).
  - `GET /me/consent` — статус согласия пользователя.
  - `POST /me/consent/withdraw` — отзыв; по Q6 после отзыва запускается удаление учётной записи (см. §4).
  - `GET /admin/users/{id}/consent` — только ТА (Q4, предложение), без значений ФИО и email.
- **Роли (ADR-0013, уточнение):** ТА — статус согласия; БА — не видит. Матрица прав дополняется строками spec 021.
- **Аудит (ADR-0006):** `pdn_consent_given`, `pdn_consent_withdrawn`. Без значений ФИО и email.
- **Экспорт (ADR-0010):** записи согласия не экспортируются (Q10, предложение). Имя и фамилия — как решено в 019.
- **Фронтенд:** блок согласия на странице регистрации; кнопка «Отозвать согласие» в профиле. Строки интерфейса — из
  `frontend/src/shared/i18n/ru.ts`. Новые файлы — в белый список теста (как в spec 007).

## 3. Задачи (черновик, статусы — после APPROVED)
1. Миграция: `consent_texts`, `user_consents`.
2. Модели и сервис `consent/`, сидирование первой версии текста с блоком ИП (после Q2 — ИНН и адрес).
3. Изменение регистрации (spec 019): поле отметки, проверка версии, запись согласия при подтверждении email.
4. Эндпоинты `/consent/current`, `/me/consent`, `/me/consent/withdraw`, `/admin/users/{id}/consent`.
5. Отзыв: запуск удаления учётной записи (только если в проекте уже есть удаление — см. §4).
6. Аудит и проверка отсутствия ФИО и email в логах и аудите.
7. Фронтенд: блок согласия в регистрации; кнопка отзыва в профиле.
8. Тесты: AC по spec 021 (`test_021_acN_*`), миграции, правила ролей, белый список фронтенда.

## 4. Открыто по spec §8 (Q6, Q7)
- Отзыв = удаление учётной записи (предложение). Если в проекте такого нет, это отдельная задача (+2–3 дня).
- Срок: «бессрочно» с оговоркой 152-ФЗ (ст. 5 ч. 7, ст. 21 ч. 5), текст — §5 spec, подтвердить юристом.

## 5. Оценка объёма (грубо, при минимальном объёме)
- Миграция, сервис, эндпоинты, аудит, тесты: 2–3 рабочих дня.
- Изменение формы регистрации (spec 019) и фронтенд: 1–2 дня.
- Отзыв с удалением учётной записи, если её ещё нет: +2–3 дня.
- Итого: **3–5 рабочих дней** без удаления учётной записи, **5–8** с ним. Не входит: юридическая проверка текста (Q12),
  выкатка на прод.

## 6. Риски
- Q7 «бессрочно»: без оговорки текст согласия может не соответствовать 152-ФЗ.
- Q9 меняет регистрацию 019: если 019 ещё не выкачена, изменения вносятся в неё до выкатки.
- Q2: без ИНН и адреса ИП текст согласия не утверждается.
- Q6: при отзыве пользователь теряет доступ к учётной записи; нужен явный сценарий.

## 7. Предложения по оставшимся вопросам (ждут подтверждения владельца)
- **Q3 (субъекты):** все регистрирующиеся пользователи — предложение.
- **Q4 (роли):** ТА — факт, версия и даты согласия; БА — ничего — предложение.
- **Q6 (отзыв):** кнопка в профиле; отзыв = удаление учётной записи в срок до 30 дней — предложение.
- **Q8 (шифрование):** шифрование диска, поля отдельно не шифровать — предложение.
- **Q10 (экспорт):** записи согласия не экспортировать; email не экспортировать — предложение.
- **Q11 (цели):** регистрация и идентификация пользователя, работа учётной записи, сброс пароля по email —
  предложение, владелец подтверждает.
- **Q12 (юрист, размещение в РФ):** проверка текста юристом до выкатки; подтвердить место хранения БД — открыт.
- **ИНН и адрес ИП:** владелец передаёт; в коде не хранятся.
