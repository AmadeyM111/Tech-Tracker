## Исходные решения владельца (2026-10-17)

Запрос владельца дословно: «в Доске задач убрать под каждым блоком "Добавить задачу"».

Уточнения владельца (переданы оркестратором; при расхождении действует текст владельца):

1. С Доски убираются кнопка «Добавить задачу» и форма создания задачи в колонках (создание из
   колонки, реализованное задачей T91 по решению владельца 2026-10-16). Остальные способы
   создания задач не трогаются.
2. Создание задачи переносится в боковое меню: кнопка «Новая задача» открывает окно (диалог) с
   выбором проекта и названием задачи.
   - В списке только проекты, где пользователь может создавать задачи. Права — серверные
     (правило создания задачи: участник проекта с возможностью `business_access`), свои правила
     интерфейс не придумывает.
   - На странице проекта этот проект выбран заранее.
   - После создания открывается карточка задачи.
   - Ошибки создания и проверка ввода — как у существующей формы создания задачи (вкладка
     «Задачи» проекта).
3. Кнопку видят все, у кого есть `business_access` (БА, «Пользователь»). У Тех-Админа и у
   пользователя без роли её нет.

## 0. Нумерация, термины, ссылки

- Нумерация своя: `FR-n`, `NFR-n`, `AC-n`, `Q-n`. Ссылки на другие спецификации — с префиксом:
  `001/FR-28`, `003/FR-10`.
- **Доска** — содержимое вкладки «Доска» карточки проекта: 4 колонки по статусам (001/FR-28),
  фильтр по исполнителю, перенос карточек.
- **Право создания в проекте** — флаг `permissions.create_task` в ответе существующего запроса
  карточки проекта `GET /api/v1/projects/{id}`. Его вычисляет сервер по правилу создания задачи
  (001/BR-1, 001/FR-19, 002/FR-9): у пользователя есть `business_access`, и он участник проекта
  (владелец считается участником). Интерфейс это правило не повторяет и не вычисляет сам.
- **Доступный проект** — проект, где у пользователя есть право создания.
- **Боковое меню** и **экраны с боковым меню** — как в 003, раздел 0. До реализации 003 —
  левая панель навигации бизнес-экранов в нынешнем виде (Q-7).
- **Диалог создания** — модальное окно, которое открывает кнопка «Новая задача».
- **Существующая форма создания** — форма «Новая задача» на вкладке «Задачи» карточки проекта
  (001/UF-3, задача T83). Эта фича её не меняет.

## 1. Контекст и цель

Сейчас под каждой колонкой Доски есть кнопка «Добавить задачу» с короткой формой ввода
названия. Владелец решил убрать её: четыре одинаковые кнопки загромождают доску, а создание
задачи из колонки, отличной от «К выполнению», требует двух запросов и может закончиться
частично (задача создана, но не перенесена). Вместо этого создание задачи становится одним
действием, доступным с любого бизнес-экрана: кнопка «Новая задача» в боковом меню открывает
диалог, где выбирается проект и вводится название, после чего открывается карточка новой
задачи. Форма на вкладке «Задачи» и создание подзадач в карточке задачи остаются как есть.
Сервер проверяет права сам, интерфейс лишь не предлагает проекты, где создавать нельзя.

## 2. Пользовательские сценарии

- Как БА или «Пользователь», я хочу видеть Доску без кнопок создания под колонками, чтобы
  доска показывала только задачи.
- Как БА или «Пользователь», я хочу создать задачу с любого экрана через «Новая задача» в
  боковом меню, выбрав проект и введя название, и сразу попасть в её карточку, чтобы
  дозаполнить остальное.
- Как пользователь на странице проекта, я хочу, чтобы этот проект уже был выбран в диалоге,
  чтобы не выбирать его заново.
- Как пользователь без доступных проектов, я хочу понять из диалога, почему создать задачу
  нельзя, а не видеть пустой список.
- Как пользователь клавиатуры и экранного диктора, я хочу открыть, заполнить и закрыть диалог
  без мыши и вернуться туда, откуда его открыл.
- Как Тех-Админ, я не хочу видеть действий бизнес-раздела, которые мне недоступны.

## 3. Функциональные требования

### 3.1. Доска без создания задач

- **FR-1:** На Доске НЕ ДОЛЖНО быть кнопки «Добавить задачу» и формы создания задачи — ни в
  колонках, ни где-либо ещё на вкладке «Доска», для любой роли и при любом значении права
  создания в проекте. С Доски НЕ ДОЛЖЕН отправляться запрос создания задачи.
- **FR-2:** Остальное поведение Доски НЕ ДОЛЖНО меняться: 4 колонки и карточки (001/FR-28),
  перенос мышью и клавиатурой с сохранением соседей (001/FR-28a), немедленное отображение
  переноса до ответа сервера и откат с сообщением при отказе (001/FR-19b), блокировка второго
  переноса, пока первый не завершён, фильтр по исполнителю и его поведение при опросе, опрос
  раз в 15 с (001/FR-29), сообщения об ошибках загрузки и переноса, объявления для экранного
  диктора.
- **FR-3:** Задача, созданная любым другим способом (FR-4), ДОЛЖНА появляться на Доске в конце
  колонки «К выполнению» (001/FR-28a) после очередного опроса или повторного открытия Доски,
  с учётом выбранного фильтра по исполнителю, как сейчас.
- **FR-4 (другие способы создания остаются):** После удаления создания с Доски задачу верхнего
  уровня ДОЛЖНО быть можно создать:
  - существующей формой создания на вкладке «Задачи» карточки проекта — без изменений (все
    поля, выбор исполнителя для БА, проверки и ошибки как сейчас);
  - диалогом создания из бокового меню (разделы 3.2–3.4).

  Создание подзадач в карточке задачи не меняется.

### 3.2. Кнопка «Новая задача» в боковом меню

- **FR-5 (кому видна):** Кнопка «Новая задача» ДОЛЖНА показываться в боковом меню каждого
  экрана с боковым меню, если у профиля сессии есть `business_access` (БА, «Пользователь»).
  Если `business_access` нет (Тех-Админ, нетипичные наборы возможностей), кнопки НЕ ДОЛЖНО
  быть. На экранах без бокового меню (вход, «Роль не назначена», окно принудительной смены
  пароля, индикатор и ошибка проверки сессии) кнопки нет. [NEEDS CLARIFICATION: показывать ли
  кнопку БА и «Пользователю» на экранах отказа в доступе к разделам ТА, если по 003/Q-2 а) там
  будет боковое меню? См. Q-6.]
- **FR-6 (вид и место):** Кнопка — элемент типа «кнопка» с доступным именем «Новая задача»,
  оформленный так же, как пункты бокового меню: с декоративной иконкой слева. Она стоит после
  последнего пункта разделов и перед кнопкой «Выйти» (003/FR-10). [NEEDS CLARIFICATION: место
  кнопки в меню. См. Q-5.]
- **FR-7 (без лишних запросов):** Пока диалог не открыт, кнопка НЕ ДОЛЖНА вызывать сетевых
  запросов. Набор и число запросов при открытии любого экрана остаются такими же, как до этой
  фичи.

### 3.3. Диалог создания: состав, список проектов, предвыбор

- **FR-8 (состав):** Нажатие «Новая задача» ДОЛЖНО открывать модальный диалог с заголовком
  «Новая задача». В диалоге:
  - поле выбора проекта с видимой подписью; можно выбрать ровно один проект;
  - поле «Название задачи» (однострочное);
  - кнопка отправки «Создать задачу»;
  - кнопка «Отмена», которая закрывает диалог без запроса создания.

  Других полей (описание, срок, приоритет, исполнитель) в диалоге нет. Они заполняются
  потом в карточке задачи. [NEEDS CLARIFICATION: тексты подписи поля проекта, пустого
  значения выбора и сообщения об отсутствии проектов. См. Q-9.]
- **FR-9 (список проектов):** Поле выбора проекта ДОЛЖНО содержать ровно доступные проекты:
  - каждый проект, для которого сервер сообщает право создания, и только их;
  - проект без права создания (например, проект, где БА не участник) в списке отсутствует;
  - все доступные проекты, а не только первая страница списка проектов (001/FR-47);
  - порядок — как в списке проектов сервера (по названию без учёта регистра);
  - показывается название проекта.

  Список читается при каждом открытии диалога. [NEEDS CLARIFICATION: список проектов сервера
  не содержит права создания, а БА получает в нём все проекты пространства. Откуда брать право
  создания без изменения бэкенда? См. Q-1.]
- **FR-10 (загрузка и ошибка списка):** Пока список загружается, диалог ДОЛЖЕН показывать
  индикатор загрузки из словаря, а отправка недоступна: запрос создания не уходит. Если список
  не загрузился (ответ не 2xx или сбой сети), диалог ДОЛЖЕН показать ровно одно сообщение об
  ошибке из словаря по коду ошибки и не отправлять запрос создания. Закрыть диалог можно. При
  следующем открытии список читается заново. Ответ 401 обрабатывается как везде: переход на
  вход (001/FR-60).
- **FR-11 (нет доступных проектов):** Если доступных проектов нет, диалог ДОЛЖЕН показать
  сообщение из словаря о том, что проектов, где можно создать задачу, нет. Поля названия и
  кнопки отправки нет, есть только кнопка закрытия. Запрос создания не отправляется.
  [NEEDS CLARIFICATION: так ли вести себя при пустом списке, или прятать либо блокировать
  кнопку? См. Q-2.]
- **FR-12 (предвыбор):** Если диалог открыт на странице проекта (`/projects/:id`, на любой
  вкладке) и этот проект доступен, он ДОЛЖЕН быть выбран заранее. Если проект страницы
  недоступен (например, БА не участник), заранее ничего не выбрано, и этого проекта в списке
  нет. На остальных экранах заранее ничего не выбрано. [NEEDS CLARIFICATION: предвыбор на
  карточке задачи и при единственном доступном проекте. См. Q-3.] Пользователь может сменить
  предвыбранный проект на любой другой из списка.

### 3.4. Диалог создания: отправка, результат, ошибки

- **FR-13 (проверка ввода):** Проверки — как у существующей формы создания:
  - название обрезается по краям; пустое или из одних пробелов название запрос НЕ отправляет,
    показывается ровно одно сообщение об ошибке ввода из словаря
    (`errorMessage("validation_error")`), диалог остаётся открытым, введённое сохраняется;
  - если проект не выбран, запрос НЕ отправляется, показывается то же сообщение;
  - длину названия проверяет сервер (1–255, 001/FR-18); его отказ 422 обрабатывается по FR-16.
- **FR-14 (запрос):** Отправка ДОЛЖНА создавать задачу существующим запросом создания задачи в
  выбранном проекте (`POST /api/v1/projects/{id}/tasks`). В теле только обрезанное название.
  Исполнителя, приоритет, срок и описание интерфейс не передаёт. Значения по умолчанию задаёт
  сервер, как для существующей формы без выбора:
  - статус «К выполнению», конец первой колонки (001/FR-18a, 001/FR-28a);
  - приоритет «Базовый»;
  - у «Пользователя» исполнитель — он сам (001/FR-20);
  - у БА исполнителя нет. [NEEDS CLARIFICATION: так ли для БА. См. Q-10.]
- **FR-15 (успех):** После успешного создания (201) система ДОЛЖНА:
  - закрыть диалог;
  - открыть карточку новой задачи (`/tasks/{id}` из ответа); переход добавляет запись в историю
    браузера, кнопка «Назад» возвращает на экран, где был открыт диалог;
  - поставить фокус на заголовок первого уровня карточки задачи, как сейчас при открытии
    карточки;
  - показать новую задачу в списке задач проекта, на Доске и в «Моих задачах» (если
    пользователь — исполнитель) при следующем открытии этих экранов, не дожидаясь опроса.
- **FR-16 (ошибка создания):** Если сервер отказал (403, 404, 409, 422, 503 и др.) или запрос
  упал с ошибкой сети, диалог ДОЛЖЕН:
  - остаться открытым на том же экране, путь не меняется;
  - показать ровно одно сообщение об ошибке из словаря по коду (`errorMessage(code)`), как
    существующая форма;
  - сохранить выбранный проект и введённое название;
  - позволить отправить снова: повторная отправка шлёт новый запрос.

  Ответ 401 — переход на вход, как везде.
- **FR-17 (повторная отправка):** Пока запрос создания выполняется, повторная отправка (Enter,
  повторный клик) НЕ ДОЛЖНА отправлять второй запрос. У кнопки отправки в это время
  `aria-busy="true"`.
- **FR-18 (закрытие во время запроса):** Пока запрос создания выполняется, Escape и «Отмена»
  диалог НЕ закрывают. «Отмена» недоступна до ответа. [NEEDS CLARIFICATION: см. Q-4.]

### 3.5. Диалог создания: доступность и фокус

- **FR-19 (семантика):** Диалог ДОЛЖЕН быть модальным окном с ролью `dialog`,
  `aria-modal="true"` и доступным именем из своего заголовка «Новая задача». Диалог не
  находится внутри ориентира навигации бокового меню. У полей видимые подписи, связанные с
  полями. Сообщения об ошибках показываются с ролью `alert` внутри диалога.
- **FR-20 (фокус):**
  - при открытии фокус ставится на поле названия, если проект выбран заранее, иначе на поле
    выбора проекта; если доступных проектов нет — на кнопку закрытия;
  - клавиша Tab и Shift+Tab обходят только элементы диалога, фокус не уходит за его пределы;
  - Escape закрывает диалог без запроса (кроме случая FR-18);
  - щелчок по подложке вне окна диалог не закрывает, как у существующих диалогов приложения;
  - после закрытия без создания (Escape, «Отмена», кнопка закрытия) фокус возвращается на
    кнопку «Новая задача»;
  - после успешного создания фокус — по FR-15.
- **FR-21 (повторное открытие):** Каждое открытие начинается заново: название пустое, сообщений
  нет, список проектов читается заново, предвыбор по FR-12 применяется заново.
- **FR-22 (один диалог):** Одновременно открыт не более чем один диалог создания. Пока он
  открыт, остальной интерфейс недоступен с клавиатуры (FR-20).

## 4. Нефункциональные требования

- **NFR-1 (бэкенд не меняется):** Серверная часть, API, OpenAPI-схема и сгенерированные из неё
  типы фронтенда НЕ ДОЛЖНЫ меняться. Используются только существующие запросы: список проектов,
  карточка проекта, создание задачи. [NEEDS CLARIFICATION: сохраняется ли это ограничение при
  выборе источника права создания. См. Q-1.]
- **NFR-2 (локализация, 001/NFR-6, 001/AC-98):** Все новые строки — из словаря. Строки, которые
  использовались только удаляемым созданием из колонки, ДОЛЖНЫ быть удалены из словаря
  (раздел 10).
- **NFR-3 (доступность, 001/NFR-7):** Диалог и кнопка работают только с клавиатуры, фокус
  виден, контраст по WCAG AA, как сейчас.
- **NFR-4 (производительность, пилотный объём 001/NFR-1, 001/FR-49):** На стенде 001/NFR-2 с
  демо-данными и с 50 проектами, в 25 из которых БА участник, список проектов в диалоге
  показывается не позднее чем через 2 с после нажатия «Новая задача» (p95 по 20 открытиям).
  Проверяется вручную, вне CI.
- **NFR-5 (совместимость и сборка):** Новых зависимостей нет. Проверки фронтенда
  (`cd frontend && npm run lint && npm run typecheck && npm test`) и полная проверка
  `bash scripts/check.sh` проходят.
- **NFR-6 (тесты):** Тесты удаляемого поведения (создание из колонки) ДОЛЖНЫ быть заменены
  тестами критериев этой спецификации, а не удалены молча. Ослаблять проверки не допускается
  (CLAUDE.md). Перечень — раздел 9.

Требований к ML-моделям нет: в фиче нет DS/ML-кода, метрик и случайности, seed не нужен.

## 5. Критерии приёмки

Если не указано иное, критерий проверяется автоматическими тестами фронтенда (vitest, Testing
Library) с подменой сети.

**Фикстуры:**

| Фикстура | Описание |
|---|---|
| `BA` | профиль `business_admin` с возможностями БА по 001/BR-11 и 002 |
| `U` | профиль `user`, только `business_access` |
| `TA` | профиль `tech_admin`: `manage_accounts`, `assign_roles`, `view_audit` |
| `NR` | профиль отвечает 403 `no_role` |
| `PWD` | профиль отвечает 403 `password_change_required` |
| `P1` «Альфа» | `permissions.create_task = true` для `BA` и `U` |
| `P2` «Бета» | для `BA` — `create_task = false` (БА не участник); для `U` проекта нет в списке |
| `P3` «Гамма» | `create_task = true` для `BA` и `U` |
| `LIST_BA` | список проектов для `BA`: P1, P2, P3 (одна страница) |
| `LIST_U` | список проектов для `U`: P1, P3 |
| `T_NEW` | ответ 201 на создание: задача с id `T_NEW` в выбранном проекте |

### 5.1. Доска без создания

- **AC-1** (FR-1): Given сессия `BA`, проект с `create_task = true`, открыта вкладка «Доска»
  When доска загружена Then:
  - ни в одной из 4 колонок нет кнопки «Добавить задачу» и вообще ни одного элемента `button`
    (в колонках только заголовок, список карточек и ссылки на задачи);
  - на вкладке нет элемента `form`, нет поля ввода названия, нет текста «Добавить задачу».

  То же для `U` с `create_task = true` и для `BA` с `create_task = false`.
- **AC-2** (FR-1): Given сценарии Доски из AC-3 (перенос мышью и клавиатурой, фильтр, опрос,
  ошибки переноса) When они выполнены Then запросов `POST /api/v1/projects/{id}/tasks` не было.
- **AC-3** (FR-2): Given существующие тесты Доски (отображение, перенос, оптимистичный перенос
  и откат, фильтр, функции расчёта соседей и места сброса) When они выполняются после
  изменения Then все проходят без ослабления проверок. Исключение — тесты создания из колонки
  из раздела 9, которые заменяются по NFR-6.
- **AC-4** (FR-3): Given выбран фильтр «Без исполнителя» When очередной опрос возвращает новую
  задачу без исполнителя в конце «К выполнению» Then карточка видна последней в колонке, фильтр
  сохранён. (Существующий тест опроса с фильтром.)
- **AC-5** (FR-3): Given выбран фильтр по исполнителю `kuznetsov` When очередной опрос
  возвращает новую задачу без исполнителя в «К выполнению» Then карточки нет, фильтр сохранён;
  When выбран фильтр «Все исполнители» Then карточка видна последней в колонке.
  (Заменяет тесты создания под фильтром, раздел 9.)
- **AC-6** (FR-4): Given сессия `BA` или `U`, проект с `create_task = true` When открыта
  вкладка «Задачи» Then существующая форма создания на месте, и создание через неё работает как
  сейчас: существующие тесты формы проходят без изменений.
- **AC-7** (FR-4): Given сессия `U` на карточке проекта P1 When на вкладке «Задачи» отправлена
  форма с названием «Проверка» Then отправлен один `POST /api/v1/projects/P1/tasks`, задача
  появилась в списке; When открыта вкладка «Доска» Then карточка «Проверка» видна в
  «К выполнению», а кнопки «Добавить задачу» нет.
- **AC-8** (NFR-2): When проверяется словарь интерфейса Then в нём нет ключей из раздела 10,
  п. 1, и нет значений «Добавить задачу» и «Задача создана в колонке …, но не перенесена».

## 7. Допущения и зависимости

- **Зависимость от 003.** Кнопка размещается в боковом меню по 003/FR-10 (состав меню,
  «Выйти» внизу). 003 сейчас в статусе DRAFT, его Q-1 (меню на экранах ТА), Q-2 (отказ в
  доступе с меню) и Q-5 (имя навигации) открыты. Для 004 существенно:
  - Q-1 003 не влияет на 004 по существу: у ТА кнопки нет в любом случае (FR-5);
  - Q-2 003 определяет, есть ли меню на экранах отказа, отсюда Q-6 004;
  - Q-5 003 (имя навигации) на 004 не влияет; диалог в любом случае вне навигации (FR-19).

  Порядок реализации 003 и 004 — Q-7.
- Право создания в проекте вычисляет сервер (`can_create_task` в правилах доступа): у
  пользователя есть `business_access`, и он участник проекта (владелец — участник). Для
  «Пользователя» это все проекты его списка, так как ему отдаются только проекты, где он
  участник. Для БА список проектов содержит все проекты пространства, а право создания есть
  только там, где он участник, — это видно только из карточки проекта (Q-1).
- Список проектов сервера постраничный: по умолчанию 50, не более 100 на странице.
- Карточка задачи уже ставит фокус на свой заголовок первого уровня при открытии; FR-15
  опирается на это.
- Создание задачи из колонки не было записано в spec 001 как требование: оно введено решением
  владельца 2026-10-16 и описано в `specs/001-pilot-r1/tasks.md` (T91) и в контракте тестов
  Доски. Поэтому снимать в 001 нечего (раздел 11).
- Оптимистичного создания на Доске нет и не было: создание из колонки ждало ответа сервера.
  Оптимистичным был и остаётся только перенос карточек (FR-2).
- Фикстуры — моки сети в тестах фронтенда. Реальные данные и GPU не нужны.

## 8. Открытые вопросы

| # | Вопрос | Варианты | Рекомендация |
|---|--------|----------|--------------|
| Q-1 | Список проектов сервера не содержит права создания, а БА получает все проекты пространства, в том числе где он не участник. Откуда брать право создания? (FR-9, NFR-1, AC-16, AC-38) | а) без изменения бэкенда: при открытии диалога прочитать все страницы списка проектов и карточку каждого проекта (`permissions.create_task`), в списке оставить проекты с `true`; б) расширить ответ списка проектов полем права создания (изменение API и OpenAPI, один запрос); в) новый параметр списка «только где могу создавать задачи» (изменение API) | **а)**. Ограничение «бэкенд не меняется» сохраняется, право берётся у сервера, а не вычисляется на клиенте (решение владельца (2)). На пилотном объёме (2 демо-проекта, 12 пользователей) лишние запросы незаметны; NFR-4 задаёт порог. Если порог не выполняется или проектов станет сотни, перейти на б) отдельной фичей. |
| Q-2 | Что делать, если доступных проектов нет? (FR-11, AC-19) | а) кнопка видна, диалог открывается и объясняет, что проектов нет; б) кнопку прятать; в) кнопка видна, но недоступна, с подсказкой | **а)**. Решение владельца (2): кнопка видна всем с `business_access`. Чтобы её спрятать или заблокировать, список пришлось бы читать на каждом экране, а это нарушает FR-7. Недоступная кнопка хуже для доступности. |
| Q-3 | Предвыбор вне страницы проекта (FR-12, AC-21) | а) ничего не выбрано; б) на карточке задачи — проект задачи; в) если доступный проект один — он выбран | **а) + в)**. Предвыбор на карточке задачи владелец не называл, а создание «рядом» с открытой задачей может ввести в заблуждение. Единственный вариант выбрать заранее безопасно: другого выбора нет, клавиатурных действий меньше. При ответе в) в AC-21 добавляется случай «один проект → выбран, фокус на названии». |
