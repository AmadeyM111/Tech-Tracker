## Исходные решения владельца

Запрос владельца (2026-10-17) дословно: «в Доске задач убрать под каждым блоком "Добавить
задачу"».

Уточнения владельца (переданы оркестратором; при расхождении действует текст владельца):

1. С Доски убираются кнопка «Добавить задачу» и форма создания задачи в колонках (создание из
   колонки, реализованное задачей T91 по решению владельца 2026-10-16). Остальные способы
   создания задач не трогаются.
2. Создание задачи переносится в боковое меню: кнопка открывает окно (диалог) с выбором
   проекта и названием задачи.
   - В списке только проекты, где пользователь может создавать задачи. Права — серверные
     (правило создания задачи: участник проекта с возможностью `business_access`), свои правила
     интерфейс не придумывает.
   - На странице проекта этот проект выбран заранее.
   - После создания открывается карточка задачи.
   - Ошибки создания и проверка ввода — как у существующей формы создания задачи (вкладка
     «Задачи» проекта).
3. Кнопку видят все, у кого есть `business_access` («Бизнес-админ», «Пользователь»). У
   «Тех-админа» и у пользователя без роли её нет.
4. (2026-10-18) Подпись кнопки — «Задача» (вместо «Новая задача»); заголовок диалога —
   «Новая задача». Вид кнопки — по образцу `docs/ui/button-task.png`: светлая кнопка-таблетка с
   иконкой «+» и подписью (на образце «Task», у нас «Задача»). Отделённую справа часть с
   шевроном (выпадающий список) не делать: кнопка одна, без выпадающего списка. Цвета — только
   через токены темы `ui.css`, контраст по WCAG AA, как у остальных кнопок и иконок проекта.

## 1. Контекст и цель

Сейчас под каждой колонкой Доски есть кнопка «Добавить задачу» с короткой формой ввода
названия. Владелец решил убрать её: четыре одинаковые кнопки загромождают доску, а создание
задачи из колонки, отличной от «К выполнению», требует двух запросов и может закончиться
частично (задача создана, но не перенесена). Вместо этого создание задачи становится одним
действием, доступным с любого бизнес-экрана: кнопка «Задача» в боковом меню открывает диалог
«Новая задача», где выбирается проект и вводится название, после чего открывается карточка
новой задачи. Форма на вкладке «Задачи» и создание подзадач в карточке задачи остаются как
есть. Сервер проверяет права сам, интерфейс лишь не предлагает проекты, где создавать нельзя.

## 2. Пользовательские сценарии

- Как БА или «Пользователь», я хочу видеть Доску без кнопок создания под колонками, чтобы
  доска показывала только задачи.
- Как БА или «Пользователь», я хочу создать задачу с любого экрана кнопкой «Задача» в боковом
  меню, выбрав проект и введя название, и сразу попасть в её карточку, чтобы дозаполнить
  остальное.
- Как пользователь на странице проекта, я хочу, чтобы этот проект уже был выбран в диалоге,
  чтобы не выбирать его заново.
- Как пользователь с единственным доступным проектом, я хочу, чтобы он был выбран сразу.
- Как пользователь без доступных проектов, я хочу понять из диалога, почему создать задачу
  нельзя, а не видеть пустой список.
- Как пользователь клавиатуры и экранного диктора, я хочу открыть, заполнить и закрыть диалог
  без мыши и вернуться туда, откуда его открыл.
- Как «Тех-админ», я не хочу видеть действий бизнес-раздела, которые мне недоступны.

## 3. Функциональные требования

### 3.1. Доска без создания задач

- **FR-1:** На Доске НЕ ДОЛЖНО быть кнопки «Добавить задачу» и формы создания задачи — ни в
  колонках, ни где-либо ещё на вкладке «Доска», для любой роли и при любом значении права
  создания в проекте. С Доски НЕ ДОЛЖЕН отправляться запрос создания задачи.
- **FR-2:** Остальное поведение Доски НЕ ДОЛЖНО меняться: 4 колонки и карточки (001/FR-28),
  перенос мышью и клавиатурой с сохранением соседей (001/FR-28a), немедленное отображение
  переноса до ответа сервера и откат с сообщением при отказе (001/FR-19b), блокировка второго
  переноса, пока первый не завершён, фильтр по исполнителю и его поведение при опросе, опрос
  раз в 15 с (001/FR-29), сообщения об ошибках загрузки и переноса, объявления для экранного
  диктора.
- **FR-3:** Задача, созданная любым другим способом (FR-4), ДОЛЖНА появляться на Доске в конце
  колонки «К выполнению» (001/FR-28a) после очередного опроса или повторного открытия Доски,
  с учётом выбранного фильтра по исполнителю, как сейчас.
- **FR-4 (другие способы создания остаются):** После удаления создания с Доски задачу верхнего
  уровня ДОЛЖНО быть можно создать:
  - существующей формой создания на вкладке «Задачи» карточки проекта — без изменений (все
    поля, выбор исполнителя для БА, проверки и ошибки как сейчас);
  - диалогом создания из бокового меню (разделы 3.2–3.4).

  Создание подзадач в карточке задачи не меняется.

### 3.2. Кнопка «Задача» в боковом меню

- **FR-5 (кому видна):** Кнопка «Задача» ДОЛЖНА показываться в боковом меню каждого экрана с
  боковым меню (003, раздел 0), если у профиля сессии есть `business_access` (БА,
  «Пользователь»). Это включает экраны отказа в доступе к разделам ТА (`/admin/users`,
  `/admin/audit`), где у БА и «Пользователя» по 003/FR-14 есть боковое меню (решение владельца,
  Q-6 а). Если `business_access` нет (ТА, нетипичные наборы возможностей), кнопки НЕ ДОЛЖНО
  быть ни на одном экране. На экранах без бокового меню (вход, «Роль не назначена», окно
  принудительной смены пароля, индикатор и ошибка проверки сессии) кнопки нет.
- **FR-6 (вид, имя и место):**
  - **Семантика.** Элемент — кнопка (роль `button`, тип `button`), не ссылка. Видимая подпись
    и доступное имя — «Задача» (доступное имя совпадает с видимой подписью, WCAG 2.5.3).
    Кнопка сообщает вспомогательным технологиям, что открывает диалог
    (`aria-haspopup="dialog"`). Признаков выпадающего списка (`aria-expanded`, меню) у неё
    нет.
  - **Вид по образцу.** Светлая кнопка-таблетка (полностью скруглённые края, как у остальных
    светлых кнопок проекта): слева декоративная иконка «+», справа подпись «Задача», в одну
    строку. Иконка «+» скрыта от вспомогательных технологий, её цвет совпадает с цветом
    подписи, и её рисунок отличается от иконок других элементов бокового меню.
  - **Отступление от образца.** На образце справа есть отделённая часть с шевроном (кнопка
    выпадающего списка). Её НЕ ДОЛЖНО быть: кнопка одна, без разделителя, без шеврона, без
    второй области нажатия и без выпадающего списка (решение владельца 2026-10-18). Подпись
    «Task» образца заменяется на «Задача».
  - **Цвета.** Фон, текст, иконка, рамка, а также состояния наведения, нажатия, фокуса и
    недоступности задаются только токенами темы; новых цветовых значений вне блока токенов
    нет. Вид по умолчанию — как у остальных светлых кнопок проекта (фон `--button-bg`, текст
    и иконка `--button-text`). Контраст подписи и иконки к фону кнопки — не ниже 4.5:1 во всех
    состояниях, где кнопка доступна; видимый фокус — рамка цвета `--focus` с контрастом не
    ниже 3:1 к фону панели (WCAG AA, 001/NFR-7).
  - **Место.** В порядке документа и визуально кнопка стоит сразу после последнего пункта
    разделов и перед кнопкой «Выйти» (003/FR-10; решение владельца, Q-5 а). «Выйти» остаётся
    последним элементом панели, прижатым к её низу.
- **FR-7 (без лишних запросов):** Пока диалог не открыт, кнопка НЕ ДОЛЖНА вызывать сетевых
  запросов. Набор и число запросов при открытии любого экрана остаются такими же, как до этой
  фичи.

### 3.3. Диалог создания: состав, список проектов, предвыбор

- **FR-8 (состав):** Нажатие «Задача» ДОЛЖНО открывать модальный диалог с заголовком
  «Новая задача». В диалоге:
  - поле выбора проекта с видимой подписью «Проект»; пустое значение выбора — «Выберите
    проект»; можно выбрать ровно один проект;
  - поле «Название задачи» (однострочное);
  - кнопка отправки «Создать задачу»;
  - кнопка «Отмена», которая закрывает диалог без запроса создания.

  В диалоге есть «Описание задачи» (обязательное), «Срок выполнения» (обязательное, по
  умолчанию «сегодня» по Europe/Moscow), у БА — «Исполнитель» (по умолчанию он сам, выбор из
  участников выбранного проекта, при смене проекта — снова он сам), у «Пользователя» — строка
  «Исполнитель: <логин>» (006/FR-20). Приоритета нет. Тексты новых строк — решение владельца
  по Q-9.
- **FR-9 (список проектов):** Поле выбора проекта ДОЛЖНО содержать ровно доступные проекты:
  - каждый проект, для которого сервер сообщает право создания, и только их;
  - проект без права создания (например, проект, где БА не участник) в списке отсутствует;
  - все доступные проекты, а не только первая страница списка проектов (001/FR-47);
  - порядок — как в списке проектов сервера (по названию без учёта регистра);
  - показывается название проекта.

  Источник права (решение владельца, Q-1 а): при открытии диалога читаются все страницы
  существующего списка проектов и для каждого проекта — существующая карточка проекта с флагом
  права создания. Новых запросов API нет (NFR-1). Список читается при каждом открытии диалога.
- **FR-10 (загрузка и ошибка списка):** Пока список загружается, диалог ДОЛЖЕН показывать
  индикатор загрузки из словаря, а отправка недоступна: запрос создания не уходит. Если список
  или карточка любого проекта не загрузились (ответ не 2xx или сбой сети), диалог ДОЛЖЕН
  показать ровно одно сообщение об ошибке из словаря по коду ошибки и не отправлять запрос
  создания. Закрыть диалог можно. При следующем открытии список читается заново. Ответ 401
  обрабатывается как везде: переход на вход (001/FR-60).
- **FR-11 (нет доступных проектов):** Если доступных проектов нет, кнопка «Задача» остаётся
  видимой и доступной, а диалог ДОЛЖЕН показать сообщение «Нет проектов, в которых вы можете
  создавать задачи». Поля названия и кнопки отправки нет, есть только кнопка «Закрыть». Запрос
  создания не отправляется (решение владельца, Q-2 а).
- **FR-12 (предвыбор):** При открытии диалога проект выбирается заранее по правилу (решение
  владельца, Q-3 а+в):
  1. диалог открыт на странице проекта (`/projects/:id`, любая вкладка), и этот проект
     доступен → выбран он;
  2. иначе, если доступный проект ровно один → выбран он;
  3. иначе заранее ничего не выбрано.

  На карточке задачи проект задачи сам по себе заранее не выбирается (действуют п. 2–3).
  Недоступный проект страницы в списке отсутствует. Пользователь может сменить предвыбранный
  проект на любой другой из списка.

### 3.4. Диалог создания: отправка, результат, ошибки

- **FR-13 (проверка ввода):** Проверки — как у существующей формы создания:
  - название обрезается по краям; пустое или из одних пробелов название запрос НЕ отправляет;
    проверка названия, описания, срока и исполнителя — сообщения у полей, как в 006/FR-19;
    диалог остаётся открытым, введённое сохраняется;
  - если проект не выбран, запрос НЕ отправляется, показывается по-прежнему
    `errorMessage("validation_error")`;
  - длину названия проверяет сервер (1–255, 001/FR-18); его отказ 422 обрабатывается по FR-16.
- **FR-14 (запрос):** Отправка ДОЛЖНА создавать задачу существующим запросом создания задачи в
  выбранном проекте (`POST /api/v1/projects/{id}/tasks`). Тело: обрезанное название, описание,
  срок; у БА — исполнитель. Приоритет не передаётся, сервер ставит «Средний» (006/FR-9);
  исполнитель по умолчанию — создатель (006/FR-17, D-4). Статус задаёт сервер: «К выполнению»,
  конец первой колонки (001/FR-18a, 001/FR-28a).
- **FR-15 (успех):** После успешного создания (201) система ДОЛЖНА:
  - закрыть диалог;
  - открыть карточку новой задачи (`/tasks/{id}` из ответа); переход добавляет запись в историю
    браузера, кнопка «Назад» возвращает на экран, где был открыт диалог;
  - поставить фокус на заголовок первого уровня карточки задачи, как сейчас при открытии
    карточки;
  - показать новую задачу в списке задач проекта, на Доске и в «Моих задачах» (если
    пользователь — исполнитель) при следующем открытии этих экранов, не дожидаясь опроса.
- **FR-16 (ошибка создания):** Если сервер отказал (403, 404, 409, 422, 503 и др.) или запрос
  упал с ошибкой сети, диалог ДОЛЖЕН:
  - остаться открытым на том же экране, путь не меняется;
  - показать ровно одно сообщение об ошибке из словаря по коду (`errorMessage(code)`), как
    существующая форма; исключение — отказ с кодом срока в прошлом: сообщение у поля срока
    (006/FR-21);
  - сохранить выбранный проект и введённое название;
  - позволить отправить снова: повторная отправка шлёт новый запрос.

  Ответ 401 — переход на вход, как везде.
- **FR-17 (повторная отправка):** Пока запрос создания выполняется, повторная отправка (Enter,
  повторный клик) НЕ ДОЛЖНА отправлять второй запрос. У кнопки отправки в это время
  `aria-busy="true"`.
- **FR-18 (закрытие во время запроса):** Пока запрос создания выполняется, Escape и «Отмена»
  диалог НЕ закрывают. «Отмена» недоступна до ответа (решение владельца, Q-4 а).

### 3.5. Диалог создания: доступность и фокус

- **FR-19 (семантика):** Диалог ДОЛЖЕН быть модальным окном с ролью `dialog`,
  `aria-modal="true"` и доступным именем из своего заголовка «Новая задача». Диалог не
  находится внутри ориентира навигации бокового меню. У полей видимые подписи, связанные с
  полями. Сообщения об ошибках показываются с ролью `alert` внутри диалога.
- **FR-20 (фокус):**
  - при открытии фокус ставится на поле названия, если проект выбран заранее (FR-12), иначе на
    поле выбора проекта; если доступных проектов нет — на кнопку «Закрыть»;
  - клавиша Tab и Shift+Tab обходят только элементы диалога, фокус не уходит за его пределы;
  - Escape закрывает диалог без запроса (кроме случая FR-18);
  - щелчок по подложке вне окна диалог не закрывает, как у существующих диалогов приложения;
  - после закрытия без создания (Escape, «Отмена», «Закрыть») фокус возвращается на кнопку
    «Задача»;
  - после успешного создания фокус — по FR-15.
- **FR-21 (повторное открытие):** Каждое открытие начинается заново: название пустое, сообщений
  нет, список проектов читается заново, предвыбор по FR-12 применяется заново.
- **FR-22 (один диалог):** Одновременно открыт не более чем один диалог создания. Пока он
  открыт, остальной интерфейс недоступен с клавиатуры (FR-20).

## 4. Нефункциональные требования

- **NFR-1 (бэкенд не меняется):** Серверная часть, API, OpenAPI-схема и сгенерированные из неё
  типы фронтенда НЕ ДОЛЖНЫ меняться. Используются только существующие запросы: список проектов,
  карточка проекта, создание задачи (решение владельца, Q-1 а).
- **NFR-2 (локализация, 001/NFR-6, 001/AC-98):** Все новые строки — из словаря: «Задача»
  (подпись кнопки), «Проект», «Выберите проект», «Нет проектов, в которых вы можете создавать
  задачи», «Закрыть». «Новая задача», «Название задачи», «Создать задачу», «Отмена» берутся из
  существующих строк. Строки, которые использовались только удаляемым созданием из колонки,
  ДОЛЖНЫ быть удалены из словаря (раздел 10).
- **NFR-3 (доступность, 001/NFR-7):** Диалог и кнопка работают только с клавиатуры, фокус
  виден, контраст по WCAG AA (FR-6), как у остальных кнопок и иконок.
- **NFR-4 (производительность, пилотный объём 001/NFR-1, 001/FR-49):** На стенде 001/NFR-2 с
  демо-данными и с 50 проектами, в 25 из которых БА участник, список проектов в диалоге
  показывается не позднее чем через 2 с после нажатия «Задача» (p95 по 20 открытиям).
  Проверяется вручную, вне CI.
- **NFR-5 (совместимость и сборка):** Новых зависимостей нет. Проверки фронтенда
  (`cd frontend && npm run lint && npm run typecheck && npm test`) и полная проверка
  `bash scripts/check.sh` проходят.
- **NFR-6 (тесты):** Тесты удаляемого поведения (создание из колонки) ДОЛЖНЫ быть заменены
  тестами критериев этой спецификации, а не удалены молча. Ослаблять проверки не допускается
  (CLAUDE.md). Перечень — раздел 9.

Требований к ML-моделям нет: в фиче нет DS/ML-кода, метрик и случайности, seed не нужен.

## 7. Допущения и зависимости

- **Зависимость от 003.** Кнопка размещается в боковом меню по 003/FR-10 и 003/FR-11
  (меню с «Выйти» внизу, в том числе на экранах ТА и экранах отказа по 003/FR-14). 003
  утверждена (v0.2) и реализуется первой (решение владельца, Q-7). Навигация бокового меню
  называется «Меню» (003/NFR-3); диалог в любом случае вне навигации (FR-19).
- Право создания в проекте вычисляет сервер: у пользователя есть `business_access`, и он
  участник проекта (владелец — участник). Для «Пользователя» это все проекты его списка, так
  как ему отдаются только проекты, где он участник. Для БА список проектов содержит все проекты
  пространства, а право создания есть только там, где он участник, — это видно только из
  карточки проекта (FR-9).
- Список проектов сервера постраничный: по умолчанию 50, не более 100 на странице.
- Карточка задачи уже ставит фокус на свой заголовок первого уровня при открытии; FR-15
  опирается на это.
- На `e43d435` все кнопки приложения по умолчанию — светлые таблетки (фон `--button-bg`, текст
  `--button-text`, полное скругление), в том числе «Выйти» на «Главной». Контраст этой пары
  около 16:1, фокус `--focus` на `--surface` не ниже 3:1 (комментарий-контракт в начале
  `ui.css`). FR-6 опирается на эти токены; новых не требуется.
- Создание задачи из колонки не было записано в spec 001 как требование: оно введено решением
  владельца 2026-10-16 и описано в `specs/001-pilot-r1/tasks.md` (T91) и в контракте тестов
  Доски. Поэтому снимать в 001 нечего (раздел 11).
- Оптимистичного создания на Доске нет и не было: создание из колонки ждало ответа сервера.
  Оптимистичным был и остаётся только перенос карточек (FR-2).
- Фикстуры — моки сети в тестах фронтенда. Реальные данные и GPU не нужны.
