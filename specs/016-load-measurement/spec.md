# Spec: Замер нормативов для «Сводки» и карточки задачи

- **ID:** 016-load-measurement
- **Статус:** DRAFT (вопросы §8 открыты)
- **Дата:** 2026-11-08
- **Пакет:** R2 T-10 в урезанном составе (решение владельца 2026-11-08: только «Сводка» и карточка).
  Основание: 001/NFR-2 (методика OI-37), 001/FR-72 (генератор), R2 NFR-09/NFR-10. Зависит от 008 и 012.

## 1. Контекст и цель
Нормативы ТЗ v1.0 §5 в R1 не замерялись (ADR-0012, SC-12). Перед масштабированием пилота нужно
подтвердить, что новые экраны R2 — «Сводка» и карточка задачи со счётчиком уведомлений — укладываются
в p95 на объёме 50 000 задач.

## 2. Функциональные требования
- **FR-1 (генератор, 001/FR-72):** `gtrack load-data --tasks 50000 --seed N` ДОЛЖЕН создавать в ПУСТОЙ
  установке синтетический набор: 12 пользователей (NFR-1), проекты, 50 000 задач с подзадачами,
  распределение статусов, приоритетов и сроков (включая просроченные и без срока), комментарии и
  уведомления. Одинаковый seed — одинаковый набор. В непустую систему — отказ (код 2).
- **FR-2 (замер):** `gtrack load-measure --base-url … --clients 5 --samples 100` ДОЛЖЕН после прогрева
  выполнять по ≥ 100 замеров каждой операции от 5 параллельных клиентов и печатать p50/p95/max:
  | Операция | Запросы | Норматив p95 |
  |---|---|---|
  | «Сводка»: плитки | `GET /me/overview` | ≤ 500 мс |
  | «Сводка»: список с фильтрами (по пресету срока, приоритету, проекту) | `GET /me/overview/tasks` | ≤ 500 мс |
  | Карточка задачи | `GET /tasks/{id}`, `GET /tasks/{id}/comments`, `GET /tasks/{id}/attachments` | ≤ 200 мс |
  | Счётчик уведомлений | `GET /me/notifications` (счётчик) | ≤ 200 мс |
- **FR-3 (отчёт):** результаты ДОЛЖНЫ записываться в `docs/acceptance/load-<дата>.md`: стенд, версия,
  seed, объём, таблица p95, вердикт по каждому нормативу.
- **FR-4 (CI):** короткий прогон той же процедуры (500 задач, 10 замеров) в CI без проверки порогов.

## 3. Нефункциональные требования
- **NFR-1:** замер только на отдельном стенде 3 vCPU / 6 ГБ и тестовой БД; не на проде пилота (R2 NFR-20).
- **NFR-2:** генератор не обращается к сети; данные синтетические.

## 4. Критерии приёмки
- **AC-1** (FR-1): два запуска с одним seed дают одинаковый `gtrack export` (без меток времени экспорта).
- **AC-2** (FR-1): запуск в непустую систему → код 2.
- **AC-3** (FR-2, FR-3): отчёт содержит все операции таблицы; каждая p95 ≤ норматива (вручную на стенде).
- **AC-4** (FR-4): короткий прогон в CI завершается с кодом 0.

## 5. Вне рамок
Доска, поиск, «Поток», CRM (R3); нагрузка записи; профилирование фронтенда.
