## NON-BLOCKING (в финальную уборку)
1. `0013:~120, ~201, ~207`: `dc` упоминается раньше определения (~244); правило и отсылка рядом есть; при желании добавить в «Откат» фразу «определите `dc` по «Командам чек-листа» до любой команды».
2. `0013:~120, ~209, ~286, ~291`: образ 001 запускается `dc up -d --build` без `--wait`; у `api` есть healthcheck (`start_period: 75s`), без `--wait` команда вернёт 0 раньше, чем `api` станет healthy, и ошибка (например, забытый `downgrade 0005`) не будет видна сразу — писать `dc up -d --build --wait`.
3. `data-model.md:~334-335`: «если из клона запущено несколько стеков» уже, чем нужно — `-p <имя>` нужен всякий раз, когда стек работает под именем, отличным от имени каталога (в ADR сказано точно, достаточно поправить формулировку).
4. `0013:~207` и `data-model.md:~332`: дописать, что `dc restart api` не пересобирает образ; если на стеке перед этим поднимали образ 001, нужен `dc up -d --build --wait` из клона на 002, а не `restart`.
