# Ревью R3-T16, попытка 1 — CHANGES_REQUESTED

Содержание ADR-0013 и правок соседних документов в целом соответствует spec 002 §10, §5.3 и коду; одна фактическая ошибка в описании отката. Прогоны (без полного набора): `test_docs_static.py` 221 passed (в том числе с маркером `infra_static`); ruff, format чисто; Python-код не менялся. ADR-0003 — изменена одна строка статуса; ADR-0004, 0006, 0012 — только добавленные строки «Уточнено ADR-0013»; чужие файлы (CLAUDE.md, STATE.md, ADR-0005, ADR-0009, glossary, open-questions, docs/reviews, docs/ui) этой задачей не тронуты (mtime 16.10 16:42). Сверка с кодом: entrypoint `set -e` → `gostracker bootstrap` → `exec uvicorn`; bootstrap: advisory-блокировка → `alembic upgrade head` → `run_bootstrap`; `env.py:43` `SET lock_timeout = 0`; порядок блокировок в 0006 (ACCESS EXCLUSIVE `workspace_member` → SHARE `app_user`); события участников нигде не пишутся (Q-5 верно); все ссылки на OI/FR/ADR/plan существуют.

## BLOCKING
1. `docs/adr/0013-three-roles.md:~116-118` и `~216-217`: откат через резервную копию описан неверно. Резервная копия 001 содержит `role='mixed'`, то есть восстановление копии роли возвращает; «по журналу» после восстановления восстанавливать нечего (записей 0006 в копии нет). Образ 001 не стартует на схеме `0006` (в нём нет ревизии, его `bootstrap` падает на `alembic upgrade head`, контейнер `api` при `set -e` не поднимается). Предложенная формулировка подраздела «Откат»: `alembic downgrade 0005` возвращает CHECK с четырьмя значениями, но роль `mixed` не возвращает и журнал не меняет; выполнять его нужно образом 002 (в образе 001 нет ревизии 0006); роли бывшим СМ возвращает ТА вручную по записям журнала (`role_from = mixed`); восстановление резервной копии 001 возвращает роли вместе со всеми данными на момент копии (изменения после копии теряются) и запускать на ней нужно образ 001 — образ 002 при старте снова выполнит 0006; автоматического восстановления ролей нет (spec §7). Пункт 5 чек-листа сократить до ссылки на этот подраздел.

## NON-BLOCKING
1. Команды чек-листа (п.1, 2, 4) не выполнимы «как написано»; в README резервное копирование помечено «отложено». Дать конкретные команды (сервис `db`, пользователь и база `tracker`): `docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > gostracker-001.dump`; выборка `workspace_member` ⨝ `app_user` по ролям `mixed`/`tech_admin`; `SELECT version_num FROM alembic_version`; выборка `domain_event` с `actor_id IS NULL` и действиями `user.role_removed`/`user.role_changed`; либо вынести команды в README (R3-T17), а в ADR оставить ссылку. Выровнять `docker compose up -d --build` с README (`… --wait`).
2. `docs/data-model.md:~302-303`: фраза «на чистой установке записей нет, как и при отсутствии пользователей с ролью `mixed` (журнал остаётся пустым)» читается так, будто без `mixed` журнал пуст; переформулировать: на чистой установке журнал пуст (001/AC-114); если пользователей с `mixed` нет, миграция 0006 записей не добавляет. Расшифровать «СМ» при первом упоминании (`:~298`).
3. `0013:~163-165`: хвост «их правка требует отдельного согласования (plan 002 §11)» устареет сразу после следующего шага; заменить устойчивой формулировкой («ADR-0005 и ADR-0009 уточняются этим ADR; где в них упоминается СМ, действуют правила этого ADR») либо убрать при правке этих файлов.
4. «Остаточный риск» (`0013:~201-205`): «при взаимной блокировке миграция откатывается целиком» → «если PostgreSQL прервёт миграцию, она откатывается целиком (FR-17)»; дописать, что новые запросы API через 30 с (`lock_timeout` сервера `db`) получают 503 `service_busy`. В строку ADR-0006 добавить по существу: обновление 0006 впервые пишет в журнал записи от «системы» (002/FR-15). В шапке ADR «FR-1…FR-17» → «FR-1…FR-22».
5. Тесты: не защищены пункты spec §10 сверх минимума и FR-15 в модели данных — мутации «удалить подраздел FR-16 / Откат / FR-7 / Замена владельца / Q-1 / «первое обновление, пишущее в журнал» / абзац про записи от «системы» в data-model.md / риск Q-5 при сохранённых «Q-5» в Альтернативах» остаются зелёными. Добавить проверки (риск Q-5 и «аудит» в «Рисках»; `первое\s+обновлени\w*.{0,80}журнал`; `FR-16`; `downgrade\s+0005`; `last_account_admin`; `первичн`; `любой\s+(активный\s+)?БА`; `actor_id = NULL` рядом с «систем» в data-model.md); у ключа отличия 3 убрать альтернативу «включая себя», проходящую на любом тексте.
