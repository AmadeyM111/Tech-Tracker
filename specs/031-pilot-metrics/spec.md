# Spec: метрики пилота к контрольной точке 2026-11-23

- **ID:** 031-pilot-metrics
- **Статус:** APPROVED (задача оркестратора 2026-11-13)
- **Дата:** 2026-11-13

## 1. Цель
К контрольной точке 2026-11-23 нужны измеримые данные пилота: сколько людей работает, сколько задач создано и закрыто, как быстро на задачи реагируют,
пользуются ли ИИ-агентами, вложениями и упоминаниями. Данные берутся из БД **только чтением**, без новой схемы и без персональных данных.

## 2. Требования
- **FR-1:** команда `gtrack pilot-report [--from ДАТА] [--to ДАТА] [--active-days N]` печатает отчёт в Markdown; границы — даты по Москве, `--to` не включается; по умолчанию — последние 14 суток; `--from` не раньше `--to`, иначе ошибка.
- **FR-2:** отчёт содержит разделы: пользователи (всего, активные за 7 дней, регистрации), задачи (создано, закрыто, открыто, просрочено), время до первой реакции (медиана, 90-й процентиль, доля с реакцией), ИИ-агенты (токены `gtrk_`, облачные клиенты OAuth, действия агентов, топ клиентов), вложения (число, задачи, объём), упоминания и уведомления; пустой раздел «Выводы» для человека.
- **FR-3 (только чтение):** запросы выполняются в транзакции `READ ONLY` (`SET TRANSACTION READ ONLY`): запись в ней невозможна; транзакция откатывается. Миграций, новых таблиц и столбцов нет.
- **FR-4 (без ПДн):** в отчёт попадают числа и названия клиентов агентов (`client_name`); логины, email, названия и тексты задач и комментариев не читаются и не выводятся.
- **FR-5:** определения метрик и ограничения описаны в `docs/pilot/README.md`; шаблон отчёта — `docs/pilot/report-template.md`.
- **FR-6:** на пустой БД отчёт строится без ошибок (нули, «нет данных»).

## 3. Критерии приёмки
- **AC-1** (FR-2): на синтетических данных отчёт показывает ожидаемые числа (пользователи, задачи, закрытые, реакции, действия агентов).
- **AC-2** (FR-3): после `collect` запись в той же транзакции отклоняется БД (`READ ONLY`), данные не меняются.
- **AC-3** (FR-1): разбор `--from/--to` даёт полуночи по Москве; `--from >= --to` — ошибка; по умолчанию 14 суток.
- **AC-4** (FR-4, FR-6): в отчёте нет `@`-адресов и логинов; пустая БД даёт нули.

## 4. Вне рамок
Запуск на проде (делает оператор); автоматическая рассылка; графики; опросы участников (в шаблоне только поля).

## 5. Оценка
≈ 1 день: запросы и вывод, CLI, тесты, документация.
