Дата: 2026-10-13. Участники: архитектор, аналитик (spec-writer), заказчик (ответы на З-1…З-12).
Документ — вход для правки `spec.md` до v0.14. После применения хранится как протокол решений.

Пометки источника: **[З]** — решение заказчика; **[А+А]** — консенсус аналитика и архитектора

## 1. Решения заказчика

| № | OI | Решение |
|---|---|---|
| З-1 | OI-1, OI-45, N-1 | **[З]** Аудит входит в R1 (ADR-0006 уточняет ADR-0002). Пишутся: создание, блокировка и разблокировка учётных записей, сброс пароля, завершение сессий; назначение, смена и снятие ролей, включая самоназначение; изменения стадий воронки; изменения сделок; передача владения проектом; архивирование проекта. Значения паролей в аудит не попадают (FR-57). Вход и неудачные попытки входа в R1 не аудируются. Журнал только дописывается: записи не удаляются и не очищаются. По бизнес-сущностям (проекты, задачи, CRM, включая названия стадий) ТА и СМ видят в журнале только метаданные: кто, когда, тип сущности, id, действие, имена изменённых полей. Значений и названий в журнале нет. |
| З-2 | OI-15, OI-61, Н-21 | **[З]** Срок задачи — календарная дата без времени (`YYYY-MM-DD`). Это явное исключение из FR-46 (ADR-0007). «Сегодня» и «просрочено» считаются по Europe/Moscow. |
| З-3 | OI-16, OI-61 | **[З]** Метки общие для всего рабочего пространства. Создают, переименовывают и удаляют БА и СМ. «Пользователь» только назначает существующие метки на свои задачи. Остальное по FR-18b. |
| З-4 | OI-60, OI-61 | **[З]** Архивирует и разархивирует владелец или СМ. В архивном проекте разрешены только чтение, скачивание вложений, разархивирование, удаление проекта и передача владения. Всё остальное, включая создание задач, перетаскивание, комментарии, вложения и состав участников, получает 409 с кодом `project_archived`. Архивный проект по умолчанию скрыт из списка проектов и из личного списка задач, виден через фильтр. Связь со сделкой сохраняется. |
| З-5 | OI-56 | **[З]** Если владелец заблокирован, нового владельца назначает СМ. Если СМ в пространстве нет, ТА выдаёт роль СМ бизнес-сотруднику, а не себе. ТА владельцев проектов не назначает. |
| З-6 | OI-57 | **[З]** Участников добавляет и исключает владелец-БА в своём проекте и СМ в любом проекте. Это намеренное сужение ТЗ §4 (ADR-0009). |
| З-7 | OI-59 | **[З]** Сделки, клиенты и контакты окончательно не удаляются. Через 30 дней они уходят из корзины, но остаются в БД, восстанавливает их только команда оператора. Кнопка окончательного удаления для них возвращает 422. Задачи, проекты, комментарии и вложения окончательно удаляются через 30 дней. Правило в AGENTS.md поправить (ADR-0010). |
| З-8 | N-5, OI-17 | **[З]** «Свой проект» — проект, где сотрудник владелец ИЛИ имеет неудалённую задачу как автор или исполнитель. В AC-48 добавить случай: владелец без задач правит чужую задачу, изменение сохранено (ADR-0009). |
| З-9 | N-8, N-9, OI-63 | **[З]** СМ читает и меняет задачи, удаляет любые комментарии в проектах, где участвует. СМ может добавить себя в любой проект. Иметь в проекте свою задачу (OI-17) для СМ не требуется. Формулировку «СМ — в любом проекте» в FR-19a, FR-5 и AC-43 читать как «в любом, где участвует» (ADR-0009). |
| З-10 | OI-33, Н-8 | **[З]** Экспорт и импорт выполняет оператор CLI-командой, вне ролей. Состав: весь workspace, пользователи с хешами паролей, роли, аудит, история, лента, метаданные и файлы вложений; сессии не входят. Формат — архив из `data.json` и `files/`. Права на файл экспорта — чтение только владельцем (как в FR-6). Импорт — только в «пустую» систему, где нет данных, кроме созданных автоматически (первый ТА, воронка по умолчанию). Импорт заменяет их и удаляет файл с паролем первого ТА; идентификаторы сохраняются. Импорт в непустую систему и импорт другой версии схемы отклоняются. «Без потерь» означает: цикл экспорт → импорт → экспорт даёт идентичный `data.json` (метка времени экспорта не сравнивается) и те же sha256 файлов. Автотест проверяет команду, а не HTTP API — это отступление от формулировки ТЗ §6 (ADR-0010). |
| З-11 | OI-44, OI-58 | **[З]** `docs/mvp.md` — черновик, уступает ТЗ; в начале файла ставится пометка об этом. Упоминания `@логин` работают только внутри приложения: счётчик, список упоминаний, признак «прочитано», обновление опросом. Упоминание не участника проекта ничего не создаёт. Правка комментария не создаёт повторного уведомления. Удаление комментария снимает уведомление (ADR-0008). |
| З-12 | Н-1 | **[З]** Последний активный обладатель права «Создание и блокировка учётных записей» не может снять с себя роль или заблокировать себя: ответ 422. |

## 2. Консенсус аналитика и архитектора

| OI / находка | Решение [А+А] |
|---|---|
| OI-2 | Поле «задача → цель» не закладывается. В plan.md записать, что связь добавляется аддитивной миграцией. |
| OI-6, Н-2 | Одна роль на пользователя в пространстве. Возможно состояние «без роли»: сразу после создания учётной записи и после снятия роли. Без роли разрешены только вход, выход и смена своего пароля, всё остальное — 403. |
| OI-9, Н-4, Н-6 | ТА нельзя сделать участником проекта, исполнителем или ответственным за сделку — 422. Заблокированного пользователя нельзя назначить исполнителем, ответственным, участником или владельцем — 422 с отдельным кодом. Недопустимый получатель (не та роль, не участник, заблокирован) всегда даёт 422, а не 403. Поправить AC-52: передача владения «Пользователю» — 422. |
| N-2 | Смена роли не трогает владение, членство в проектах, исполнителей и ответственных. Права определяет текущая роль. Такие записи находят и переназначают БА и СМ, как при блокировке (FR-5). |
| Н-3 | Смена роли действует со следующего запроса; права не кешируются в сессии. Нужен AC. |
| OI-45 | В spec записывается только результат: событие появляется в истории сделки, ленте и аудите вместе с самим изменением, частичная запись невозможна. Способ реализации («одна таблица») — в plan.md. Срок хранения событий — бессрочно, с учётом Н-10. |
| Н-10 | После окончательного удаления события ленты и аудита остаются, объект показывается как «объект удалён» без содержимого. При окончательном удалении проекта связь сделки с ним снимается, в историю сделки пишется запись с автором «система». |
| OI-23 | На доске показываются только задачи верхнего уровня; подзадачи видны в карточке вместе с прогрессом. Позиции FR-28a есть только у задач верхнего уровня. Подзадачи попадают в список задач и в личный список. «Число задач» в FR-17 считает только задачи верхнего уровня. |
| N-3 | Если статус меняется не перетаскиванием (из карточки или через API), задача встаёт в конец целевой колонки. Нужен AC. |
| OI-24 | Опрос работает на экранах: доска, список задач, карточка задачи, карточка сделки, список сделок, ленты, счётчик упоминаний. Механизм — в plan.md. |
| Н-13 | Фоновые запросы опроса не продлевают 8-часовой тайм-аут неактивности (FR-59). Нужен AC. |
| OI-25 | Клиент — организация; ИП тоже считается организацией. Поля: название (обязательно, 1–255), ИНН (необязательно, 10 или 12 цифр, уникален среди неудалённых клиентов пространства), телефон, email, сайт, адрес, заметка. Предельные длины полей задаются в spec. Физлица — в R2. |
| OI-26 | Поля контакта: ФИО (обязательно), должность, телефон, email, заметка. Контакт принадлежит ровно одному клиенту. Сделка связана с 0..N контактами, и они должны принадлежать клиенту сделки, иначе 422. Смена клиента у сделки с привязанными контактами — 422 «сначала отвяжите». |
| OI-27 | Поля сделки: название (обязательно), клиент (обязательно), сумма (обязательно, целое число от 0 до 10^14 копеек, иначе 422), валюта RUB, стадия (по умолчанию первая стадия типа open), ответственный — активный БА или СМ (по умолчанию создатель), контакты 0..N, проект 0..1. |
| OI-12 (остаток) | Контакты добавляются в FR-25. Клиента с неудалёнными сделками удалить нельзя — 422. Удаление клиента мягко удаляет его контакты, восстановление клиента возвращает контакты, удалённые вместе с ним. Восстановление сделки при удалённом клиенте — 422. |
| OI-28 | Воронка одна на пространство. У стадии есть название (уникальное в воронке, с предельной длиной), порядок и тип ∈ {open, won, lost}. Управляют стадиями БА и СМ. Должно быть не меньше одной активной стадии open и ровно одна активная won и одна активная lost. Удалить можно только стадию, в которой никогда не было сделок; иначе стадию можно только архивировать. Архивная стадия не предлагается для новых сделок и переходов, сделки в ней остаются и видны; стадию можно разархивировать. Переходы свободные. При первом запуске создаются стадии: «Новая», «Квалификация», «Предложение», «Переговоры», «Выиграна», «Проиграна». |
| Н-18 | Воронка в R1 — список сделок с фильтром по стадии плюс счётчики и суммы по стадиям. Стадия меняется полем. Доска сделок — вне рамок R1. |
| OI-29 | Связь сделки с проектом 1:1. Связать с удалённым проектом — 422, с архивным — можно. Повторная связь уже связанного проекта или сделки — 422. Связь ставит и снимает роль с правом «CRM: изменение»; участвовать в проекте для этого не нужно. Способ реализации — в plan.md. |
| OI-30, Н-19 | Роли без права «CRM: чтение» на странице проекта не видят ничего о сделке: поля нет в ответе. На странице сделки задачи проекта видит только участник проекта; остальным показывается название проекта и «нет доступа к задачам». Задачи показываются постранично (FR-47) с полями: название, статус, исполнитель, срок, приоритет. На странице проекта сделка показывается с полями: название, стадия, сумма, ответственный. |
| OI-31 | Лента проекта: задачи (создание, смена статуса, исполнителя или срока, удаление, восстановление), комментарии (без текста), вложения, участники, владение, архив. CRM-событий в ленте проекта нет. Лента сделки: создание, переходы по стадиям, изменение суммы и ответственного, связь с проектом, контакты. Правка названия или описания — событие без значений. |
| OI-32 | Поиск ищет задачи и проекты с учётом прав, клиентов и сделки — только для ролей с CRM; контакты не ищутся. Совпадение по подстроке без учёта регистра. Запрос короче 2 символов — 422. До 20 результатов на тип — явное исключение из FR-47. Архивные проекты в поиск входят. |

Несуществующий, окончательно удалённый или мягко удалённый (вне корзины) объект — 404. Объект другого пространства — 404. |
