# Регламент ревью v2 (с 2026-10-15)

Цель — сократить время ревью без потери ловли дефектов. Источник: замеры времени ревью T26…T82
(среднее ≈ 11 мин, 1,5–2 ревью на задачу; основной вклад — полный прогон тестов и ручные мутации).

## Уровни проверки
| Когда | Что |
|---|---|
| Каждая задача | линтеры/типы; целевые тесты задачи; мутации ТОЛЬКО по строкам `git diff --cached` (потолок 15); один живой сценарий по затронутым AC |
| Повторное ревью (после правок) | только дельта: тесты и мутации по изменённым строкам |
| Конец среза (R1.x) / приёмка | полный регресс, полный живой прогон по всем сценариям |
| Перед релизом | полное мутационное тестирование |

## Правила
1. Реализатор сдаёт `check.sh` зелёным; ревьюер НЕ повторяет его целиком: сверяет хеш индекса
   (`git write-tree`) с указанным в отчёте и запускает только целевые тесты задачи.
2. Живой стенд — по затронутым AC; полный набор сценариев — в конце среза.
3. Таймауты этапов: тесты 5 мин, живой стенд 10 мин, мутации 5 мин; превышение — в отчёт как риск.
4. Нестабильные тесты (docker-коллизии образов `gostracker-web:test`, часы) — в карантин-список
   отчёта, не повторяются в ревью.
5. Во время ревью БД ревьюера — отдельная (`tracker_<task>rev_test`); docker-тесты в параллельных
   потоках не запускаются.
6. В отчёте ревью — время этапов (тесты / стенд / мутации).
7. Задача > 6 файлов кода или > 8 AC дробится архитектором.
