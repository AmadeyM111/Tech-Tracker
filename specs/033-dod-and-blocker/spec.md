# Spec: критерий готовности (DoD) и блокер

- **ID:** 033-dod-and-blocker
- **Статус:** DRAFT
- **Дата:** 2026-11-16
- **Кастдев:** CD-01 + CD-03, 2026-11-16
- **ADR:** 0029
- **Миграция:** 0019 (`down_revision` 0018)

## 1. Контекст и цель
Команда 8–10 не ставит статусы; галка «Готово» врёт. Агент по MCP не должен закрывать
задачу сам. «Горит» сейчас = высокий приоритет и срок сегодня или раньше (спека 008 FR-8);
для ПМ «горит» — инцидент и блокер, не внутренний дедлайн. Нужен признак завершения
по критериям и отдельная метка блокера, без ломания 008 AC-8.

## 2. Пользовательские сценарии
- Как ПМ, я хочу список обязательных критериев у задачи, чтобы «Готово» нельзя было поставить враньём.
- Как исполнитель, я хочу отмечать критерии, не меняя колонки доски.
- Как ПМ, я хочу, чтобы агент отмечал критерии, но не ставил `done`.
- Как ПМ, я хочу метку «Блокер» на доске и сводке, отдельно от «Горит» по сроку.

## 3. Функциональные требования

### CD-01 DoD
- **FR-1:** У задачи есть список критериев: `id`, текст (1–500), обязательный, отмечен,
  кто отметил, когда. Порядок — `position`. Подзадачи не подменяют DoD родителя.
- **FR-2:** Шаблон критериев у проекта в этом срезе нет (дорого относительно пользы);
  критерии задаются на задаче.
- **FR-3:** Перевод в `done` (PATCH и перенос на доске) запрещён, пока открыт хотя бы один
  обязательный критерий: 422 `dod_open`, в `detail` список текстов открытых обязательных.
  Необязательные на `done` не влияют. Задача без критериев закрывается как раньше.
- **FR-4:** Флаг `human_close_only` у задачи по умолчанию `true`. При нём запрос с именем
  MCP-клиента (`client_name`) не ставит `done`: 403 `human_close_only`. Отметить критерий
  агент может. Человек (веб, без `client_name`) ставит `done` при закрытых обязательных.
- **FR-5:** Отметить или снять отметку критерия могут: исполнитель, автор, владелец проекта,
  БА-участник. Добавлять, править текст, обязательность и удалять критерии — кто имеет
  полную правку задачи (`can_edit_task_fully`).
- **FR-6:** `GET /tasks/{id}` и MCP `get_task` отдают `dod`: `closed`, `total`, `human_close_only`,
  `items`. Карточка показывает «N из M».
- **FR-7:** REST: `POST /tasks/{id}/dod-criteria`, `PATCH /tasks/{id}/dod-criteria/{id}`,
  `DELETE /tasks/{id}/dod-criteria/{id}`. MCP: `check_dod_criterion` (запись отметки);
  чтение — через `get_task`.

### CD-03 Блокер
- **FR-8:** У задачи `blocked`, `blocked_reason` (1–500, обязателен при постановке),
  `blocked_by`, `blocked_at`. Снятие обнуляет причину, кто и когда; статус не меняет.
- **FR-9:** Метка «Горит» (`hot`) остаётся правилом 008 FR-8. Метка «Блокер» — отдельное
  поле `blocked` на сводке, доске и карточке. Их не смешивать.
- **FR-10:** MCP и REST ставят и снимают блокер полями `blocked` / `blocked_reason` в
  `update_task`. `list_project_tasks` принимает `blocked=true|false`.
- **FR-11 (done+blocked):** поставить блокер на `done` нельзя (422 `task_already_done`);
  поставить `done` при `blocked` нельзя (422 `task_blocked`). Сначала снимают блокер.

## 4. Нефункциональные требования
- **NFR-1:** миграция 0019 аддитивна: колонки `task` и таблица `task_dod_criterion`.
- **NFR-2:** существующие задачи: `blocked=false`, `human_close_only=true`, критериев нет.
- **NFR-3:** UI-тексты на русском; касание 44 px у чекбокса и кнопок критериев.

## 5. Критерии приёмки
- **AC-1** (FR-3): Given 2 обязательных критерия, 1 открыт When PATCH `status=done` Then 422 `dod_open`, статус прежний.
- **AC-2** (FR-3): Given все обязательные отмечены When PATCH `done` Then 200.
- **AC-3** (FR-4): Given агент MCP When отмечает критерий Then 200 и событие с `client_name`; When ставит `done` при `human_close_only` Then 403 `human_close_only`.
- **AC-4** (FR-1): Given открытый обязательный критерий родителя и все подзадачи `done` When PATCH родителя `done` Then 422 `dod_open`.
- **AC-5** (FR-9): Given `medium` без срока и `blocked=true` When сводка Then `blocked=true` и `hot=false`.
- **AC-6** (FR-9, 008 AC-8): Given `high` + срок сегодня без блокера When сводка Then `hot=true` (как 008 AC-8).
- **AC-7** (FR-11): Given задача `done` When `blocked=true` Then 422 `task_already_done`.
- **AC-8** (FR-11): Given `blocked=true` When PATCH `done` Then 422 `task_blocked`; When снять блокер Then статус не `done`.
- **AC-9** (FR-10): Given две задачи, одна с блокером When `list_project_tasks?blocked=true` Then только блокеры.

## 6. Вне рамок
- Авто-вывод готовности из git/логов; смена колонок доски; напоминания; мониторинг uptime;
  шаблон DoD у проекта; ingest Telegram; `list_stuck_work`; `is_agent`.

## 7. Допущения и зависимости
- Спека 008 FR-8 не меняется. MCP `client_name` уже пишется в журнал (ADR-0018).
- Права БА — только участник проекта (PR #62).
