# Spec: агент как коллега (атрибуция MCP в карточке и списке)

- **ID:** 022-agent-accounts
- **Статус:** DRAFT (срез CD-05; отдельная учётка агента — следующий срез)
- **Дата:** 2026-11-16
- **Связано:** ADR-0018, ADR-0031, `020-mcp-ai-native`, кастдев ПМ 2026-11-16 (CD-05)

## 1. Контекст и цель
Агент уже действует от имени пользователя (PAT / OAuth) и пишет `domain_event.client_name`
(имя токена или OAuth `client_name`). В ленте проекта поле `via_client` есть, но в карточке
задачи, списке и на доске человек и агент неразличимы: исполнитель всегда человек, а «кто
последний трогал» не видно. Нужен срез «агент как коллега»: метка «ИИ» и имя клиента там,
где смотрят задачи. Отдельная учётка (`app_user.is_agent`) в этом PR не вводится — иначе
столкновение с 0019/0020.

## 2. Пользовательские сценарии
- Как участник проекта, я хочу на карточке задачи видеть, что последнее изменение сделал
  агент (имя токена / клиента), чтобы не путать его с правкой коллеги в веб-интерфейсе.
- Как участник, я хочу в списке задач и на доске видеть метку «ИИ», если последнее
  изменение или последнее назначение исполнителя пришло от агента.
- Как участник, я хочу по имени клиента отличить «Claude Code на ноутбуке» от человека.

## 3. Функциональные требования
- **FR-1 (источник):** Система ДОЛЖНА определять агента по `domain_event.client_name`
  (имя PAT или OAuth `client_name`, 1–64 символа). Миграция `app_user.is_agent` в этом
  срезе ЗАПРЕЩЕНА (ADR-0031).
- **FR-2 (последнее изменение):** В ответах карточки задачи (`TaskDetail`), списка
  (`TaskListItem`) и карточки доски (`BoardCard`) ДОЛЖНО быть поле `last_client_name`:
  `client_name` последнего события с `entity_type=task` и `entity_id` этой задачи;
  `null`, если последнего события нет или оно из веб-интерфейса (`client_name` пуст).
- **FR-3 (исполнитель):** В тех же схемах ДОЛЖНО быть поле `assignee_client_name`:
  `client_name` последнего события, которое задало исполнителя (`task.created` или
  `task.updated` с `assignee_id` в `changed_fields`); `null`, если назначения не было
  или его сделал человек в вебе.
- **FR-4 (UI карточка):** На карточке задачи (`/tasks/:id`) при непустом
  `last_client_name` ДОЛЖНА быть метка «ИИ» и имя клиента рядом с заголовком. При
  непустом `assignee_client_name` — та же метка рядом с исполнителем. Имя человека —
  `personName` (фамилия и инициал, не логин, если имя есть).
- **FR-5 (UI список и доска):** То же в таблице/карточках списка задач и на канбан-карточке.
  Человек без агентского события метки «ИИ» не получает.
- **FR-6 (права MCP без изменений):** Удаление задач/проектов, роли, состав участников
  и учётные записи через MCP по-прежнему закрыты (ADR-0018 п. 7).

## 4. Нефункциональные требования
- **NFR-1:** без новой колонки на `task` и без `is_agent`; чтение атрибуции — пакетный
  запрос к `domain_event` по id страницы/доски (не N+1).
- **NFR-2:** UI-кит: тёмная тема, контраст AA; интерактив 44 px; метка «ИИ» — не кнопка.
- **NFR-3:** новых исходящих вызовов, харнесса, A2A и ключей `gtk_` нет.

## 5. Критерии приёмки
- **AC-1** (FR-2, FR-4): Given задача создана через MCP с именем токена «Claude Code»
  When открыта карточка Then видна метка «ИИ» и текст «Claude Code»; `last_client_name`
  в JSON равен этому имени.
- **AC-2** (FR-2, FR-5): Given то же When список проекта и доска Then метка «ИИ» и имя
  клиента есть у этой задачи и нет у задачи, изменённой только в вебе.
- **AC-3** (FR-2): Given задачу создал агент, затем человек сменил статус в вебе When
  карточка и список Then `last_client_name` = `null`, метки «ИИ» у заголовка нет.
- **AC-4** (FR-3): Given агент назначил исполнителя, затем человек изменил название When
  карточка Then у заголовка метки нет, у исполнителя — «ИИ» и имя клиента
  (`assignee_client_name`).
- **AC-5** (FR-1): Given схема `app_user` When миграции этого PR Then колонки `is_agent` нет.
- **AC-6** (FR-6): Given `tools/list` When просмотр Then нет инструментов удаления,
  ролей, участников и учёток.

## 6. Вне рамок (Out of scope)
- Учётка агента, `app_user.is_agent`, ключи `gtk_` / `GT-12`, A2A, свой харнесс.
- Удаление, роли, состав проекта через MCP.
- Смена модели прав: агент по-прежнему действует от имени владельца токена.

## 7. Допущения и зависимости
- События задач уже пишутся с `client_name` в MCP (`client_name_scope`, ADR-0018).
- Индекс `ix_domain_event_entity_type_entity_id` достаточен для страницы ≤ 100 задач.
- Следующий срез 022: отдельная учётка агента, если продукт решит, что имени клиента мало.
