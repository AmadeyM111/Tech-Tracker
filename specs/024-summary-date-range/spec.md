# Spec: «Сводка» — диапазон дат срока «с / по»

- **ID:** 024-summary-date-range
- **Статус:** APPROVED (решения владельца по §8 — 2026-11-10: «по спеке R3 положительное решение»)
- **Дата:** 2026-11-10
- **Пакет:** R3. Основание: R2-1d (диапазон дат перенесён из R2 в R3, решение владельца 2026-11-08, Q-14), `008-summary` (пресеты срока), ADR-0007 (Europe/Moscow). Макеты: `Shared/Design/gtrack-r3/` (`range-empty`, `range-set`, `range-error`), тексты — предложения.

## 1. Контекст и цель
Пять пресетов срока «Сводки» (008/FR-7) не отвечают на вопрос «что у меня на конкретную неделю или
между двумя датами». Нужен свободный диапазон по календарным датам Москвы. Диапазон не заменяет
пресеты, а дополняет их: в один момент действует либо пресет, либо диапазон (предложение, Q-1).
Остальные правила «Сводки» (плитки, «Нужно проверить», «Горит», сортировка, 15-секундный опрос) не меняются.

## 2. Пользовательские сценарии
- Как участник, я задаю «с 16.11 по 20.11» и вижу задачи со сроком в эти дни, чтобы спланировать неделю.
- Как участник, я задаю только «с» или только «по», чтобы увидеть «всё после» или «всё до» даты.
- Как участник, я выбираю пресет, и диапазон очищается (и наоборот), чтобы не гадать, какое условие действует.

## 3. Функциональные требования
- **FR-1 (параметры):** `GET /api/v1/me/overview/tasks` ДОЛЖЕН принимать `due_from` и `due_to`
  (даты `YYYY-MM-DD`, календарные даты Москвы, границы включительно). Каждый параметр необязателен;
  заданный один — полуоткрытый диапазон (Q-2). Параметры могут повторяться не более одного раза (как `due`).
- **FR-2 (взаимоисключение):** если задан `due` (пресет) вместе с `due_from` или `due_to`, API ДОЛЖЕН отвечать 422
  `validation_error` (Q-1). Если `due_from > due_to` — 422. Неверный формат даты — 422.
- **FR-3 (условие):** диапазон ДОЛЖЕН отбирать задачи с `due_date` внутри диапазона; задачи без срока в выборку
  с диапазоном не попадают. Статус `done` не исключается (диапазон — чистая выборка по дате, в отличие от
  «Просрочено», Q-3). Сочетается через «И» с проектом, статусом, приоритетом и «Нужно проверить».
- **FR-4 (плитки и «Горит»):** плитки не зависят от диапазона (008/Q-2); метка «Горит» считается как раньше.
- **FR-5 (интерфейс):** под пресетами срока ДОЛЖЕН быть блок (пунктирная рамка) с полями «с» и «по» (`<input type="date">`)
  и подписью «даты по Москве». Выбор любого поля снимает пресет (`aria-pressed=false`); выбор пресета очищает оба поля.
  Состояния — пусто, задан, ошибка (макеты).
- **FR-6 (ошибка):** при `с` > `по` интерфейс ДОЛЖЕН подсветить поле «с» (`--danger`, `aria-invalid`), показать
  текст «Дата «с» не может быть позже даты «по»» со значком под блоком (`role="alert"`, связь `aria-describedby`)
  и НЕ отправлять запрос; список остаётся прежним (Q-4).
- **FR-7 («Показано N из M»):** строка количества, пагинация и опрос 15 с работают с диапазоном как с любым фильтром;
  смена диапазона возвращает на страницу 1.
- **FR-8 (хранение):** диапазон не сохраняется между сеансами (как и остальные фильтры, 008 §7).

## 4. Нефункциональные требования
- **NFR-1:** p95 ≤ 500 мс на 50 000 задач (R2 NFR-09); замер `scripts/explain_r2_queries.py` дополняется случаем диапазона.
- **NFR-2:** изоляция по `workspace_id` и членству — без изменений; новых исходящих запросов нет.
- **NFR-3:** строки в `ru.ts`; клавиатура; контраст WCAG AA; поля даты ≥ 44 px; 360 px без горизонтальной прокрутки.
- **NFR-4:** миграций нет; индекс по замеру не требуется (`r2-explain-50k.md`), иначе — отдельное решение.

## 5. Критерии приёмки
- **AC-1** (FR-1, FR-3): Given задачи со сроками вчера, сегодня, +3 дня, +10 дней, без срока When `due_from=сегодня&due_to=+3` Then в выборке задачи «сегодня» и «+3»; границы включены.
- **AC-2** (FR-1): Given тот же набор When только `due_from=сегодня` Then все срока ≥ сегодня, без «вчера» и «без срока»; только `due_to` — симметрично.
- **AC-3** (FR-3): Given `done` со сроком в диапазоне When диапазон Then задача есть в списке (в «Просрочено» её нет).
- **AC-4** (FR-2): Given `due=today&due_from=…` When запрос Then 422; `due_from > due_to` — 422; `due_from=31.12.2026` — 422; повтор `due_to` дважды — 422.
- **AC-5** (граница суток): Given часы 21:00Z (00:00 МСК) When диапазон `due_from=due_to=сегодня` Then выборка совпадает с пресетом «Сегодня» (тот же `today_msk`).
- **AC-6** (FR-4): Given диапазон When `GET /me/overview` Then плитки те же, что без диапазона.
- **AC-7** (FR-5): Given выбран пресет «Завтра» When введена дата «с» Then `aria-pressed=false` у всех пресетов и запрос идёт без `due`; When выбран пресет Then поля пусты.
- **AC-8** (FR-6): Given «с» 13.11, «по» 09.11 When ввод Then видно сообщение, поле «с» `aria-invalid`, нового запроса списка нет.
- **AC-9** (FR-7): Given страница 2 When меняется «по» Then запрошена страница 1.

## 6. Вне рамок
Фильтр по дате создания/изменения; диапазоны быстрых выборов («Прошлая неделя»); часовые пояса пользователя; сохранение фильтров; CSV (спека 025, использует те же параметры).

## 7. Допущения и зависимости
- Зависит от `008-summary` (в main). Спека 025 (CSV) принимает те же параметры; порядок слияния 024 → 025 (иначе CSV сначала без диапазона).
- Нативный `<input type="date">` показывает дату в формате браузера; ручной ввод и маска — не делаем.

## 8. Решения по вопросам (владелец, 2026-11-10)
Все рекомендации приняты: Q-1 диапазон и пресет взаимоисключающие; Q-2 можно задать только «с» или только «по»; Q-3 завершённые (`done`) задачи в диапазоне показываются; Q-4 при «с» позже «по» — ошибка, запрос не уходит; Q-5 ограничения длины диапазона нет; Q-6 подпись «даты по Москве».
