# Spec: «Сводка» — плитки, «Нужно проверить», фильтры по приоритету и сроку, CSV, метка «Горит»

- **ID:** 008-summary
- **Статус:** DRAFT (решения владельца 2026-11-08 учтены; открытые вопросы — §8)
- **Дата:** 2026-11-08
- **Пакет:** R2 T-03 «Сводка и CSV» (CSV и диапазон дат — в пакете). Карточка «Подключить ИИ-агента» — отдельная спека T-13 в R2, в пакет не входит (§7).
  Основание: решения владельца 2026-11-08 (`r2-dev-task-list.md`, Q-7, Q-13, Q-14, Q-15; `r2-tz-amendments.md`,
  R2-1a…R2-1d, R2-2, R2-3); ADR-0006, ADR-0007, ADR-0012, ADR-0013.
  Макет `Shared/Design/summary-r2-design.md` отстаёт от решений: помечает CSV, диапазон дат и карточку как R3.
  До его обновления и утверждения P-S1 (§8, Q-9) спека опирается на текст ТЗ и решения, не на макет.

## 1. Контекст и цель
В R1 нет общего списка задач по всем проектам и фильтра по сроку (001/FR-27a отложен, ADR-0012).
Участник пилота должен одним экраном видеть, сколько задач в каждом статусе, что ждёт его проверки,
что просрочено и что горит. Экран «Сводка» закрывает 001/FR-27a и R2-1a…R2-1d. В пакет входят также
CSV-выгрузка для БА (R2-2, R2-3) и диапазон дат в фильтре по сроку (Q-14 задачного списка).
Карточка «Подключить ИИ-агента» (T-13) — отдельная спека в R2, следующий шаг; здесь не реализуется.
Фильтр по исполнителю и метки в пакет не входят (исполнитель — открытый вопрос Q-11).

## 2. Пользовательские сценарии
- Как участник, я хочу видеть число задач по статусам во всех моих проектах, чтобы понимать объём работы.
- Как автор задачи или владелец проекта, я хочу видеть задачи, которые ждут моей проверки.
- Как участник, я хочу отфильтровать задачи по проекту, статусу, приоритету и сроку, чтобы найти горящее.
- Как участник, я хочу задать свой период сроков («с» и «по»), если пресеты не подходят.
- Как БА, я хочу выгрузить в CSV задачи, которые вижу в списке с текущими фильтрами, чтобы открыть их в Excel.
  Выгрузка видна в аудите.
- Как техадминистратор, я не вижу «Сводку»: бизнес-данные мне недоступны (ADR-0013).

## 3. Термины
- **Мои проекты** — неудалённые проекты пространства, где пользователь владелец или участник
  (`project.owner_id` или строка `project_member`), как у `can_read_project_content`.
- **Задачи сводки** — неудалённые задачи и подзадачи моих проектов (подзадачи наравне, Q-1 — решено).
- **Выборка списка** — задачи сводки, прошедшие все фильтры списка, по всем страницам. Состав CSV = выборка списка (FR-13).
- **Сегодня** — `today_msk()` (ADR-0007). Срок хранится как дата `YYYY-MM-DD`.

## 4. Функциональные требования
- **FR-1:** Система ДОЛЖНА показывать пункт «Сводка» в боковом меню пользователям с `business_access`
  и экран `/summary`.
- **FR-2 (плитки, R2-1a):** Экран ДОЛЖЕН показывать плитки «Всего», «Не начато» (`todo`), «В работе»
  (`in_progress`), «На проверке» (`review`), «Готово» (`done`) с числом задач сводки. Сумма четырёх
  статусов ДОЛЖНА равняться «Всего». Плитки НЕ зависят от фильтров списка (Q-2 — решено): считаются
  по всем задачам сводки.
- **FR-3 («Нужно проверить», R2-1b):** Экран ДОЛЖЕН показывать отдельную плитку «Нужно проверить»:
  задачи сводки в `review`, где пользователь автор задачи (`created_by`) или владелец проекта
  (Q-13 задачного списка — решено 2026-11-08).
- **FR-4 (переход по плитке):** Нажатие на плитку статуса ДОЛЖНО открывать список с фильтром этого
  статуса; «Всего» — без фильтра статуса; «Нужно проверить» — с фильтром `needs_review=true`.
- **FR-5 (список):** Экран ДОЛЖЕН показывать постраничный список выборки с колонками «Проект»,
  «Задача», «Статус», «Приоритет», «Исполнитель», «Срок»; строка открывает карточку задачи.
  Порядок — по сроку по возрастанию, без срока в конце, тай-брейкер — `id` (Q-6 — решено).
- **FR-6 (фильтры):** Список ДОЛЖЕН фильтроваться по проекту (один из моих проектов), статусу (одно
  значение, Q-7), приоритету `low`/`medium`/`high` (мультивыбор, R2-1c) и сроку (FR-7). Фильтры
  объединяются через «И».
- **FR-7 (срок, R2-1d, 001/FR-27a, Q-14 задачного списка — решено):** Пресеты срока по Europe/Moscow:
  - «Просрочено» — `due_date < сегодня`;
  - «Сегодня» — `due_date = сегодня`;
  - «Завтра» — `due_date = сегодня + 1`;
  - «На этой неделе» — `сегодня ≤ due_date ≤ воскресенье` текущей календарной недели (Q-4 — решено:
    прошедшие дни недели не входят, они в «Просрочено»);
  - «Без срока» — `due_date IS NULL`.
  
  Диапазон дат: параметры `due_from` и `due_to` (`YYYY-MM-DD`, границы включительно). `due_from > due_to`
  → 422. Сочетание пресета и диапазона, пустая одна граница — Q-12, Q-13.
  Задачи в `done`: в «Просрочено» не входят (Q-3 — решено); в «Сегодня», «Завтра», «На этой неделе» —
  открыто (Q-14).
- **FR-8 («Горит»):** Строка списка ДОЛЖНА нести метку «Горит», если приоритет `high`, `due_date <= сегодня`
  и статус не `done` (Q-3 — решено). Метка — текст, не только цвет.
- **FR-9 (количество):** Над списком ДОЛЖНА быть строка «Показано N из M», где N — строк на текущей
  странице, M — число задач выборки (Q-5 — решено).
- **FR-10 (пусто):** Если задач сводки нет, вместо списка ДОЛЖЕН показываться текст «Задач пока нет.
  Они появятся, когда вас добавят в проект или вы создадите задачу.»; плитки остаются с нулями.
- **FR-11 (права):** API сводки ДОЛЖНО отвечать 403 пользователю без `business_access` (ТА) и 401
  без сессии. Фильтр по чужому проекту (не мой, удалённый, другого пространства) ДОЛЖЕН давать 404
  (тот же ответ, что у проекта, которого нет).
- **FR-12 (обновление):** Плитки и список ДОЛЖНЫ обновляться опросом раз в 15 с (`POLL_INTERVAL_MS`).
- **FR-13 (CSV, R2-2, R2-3, T-03 F4–F5):** Эндпоинт `GET /api/v1/me/overview/tasks.csv` с теми же
  фильтрами, что FR-6 и FR-7, ДОЛЖЕН отдавать выборку списка в CSV только роли БА (`business_admin`,
  ADR-0013). Для пользователя (П) и ТА — 403; без сессии — 401.
  - Формат: UTF-8 с BOM, разделитель «;», первая строка — заголовки.
  - Колонки: проект, задача, статус, приоритет, исполнитель, срок, дата создания, дата изменения, ссылка на карточку.
  - Состав: выборка списка, а не только текущая страница (вид выборки и лимит строк — Q-15).
  - Кнопка «Скачать CSV» на экране ВИДНА только БА.
  - Экранирование ячеек — Q-17.
- **FR-14 (аудит выгрузки, R2-3, T-03 F6):** Каждая успешная выгрузка ДОЛЖНА записываться в журнал
  аудита: кто, когда, сколько строк. Значений полей задач в событии нет (ADR-0006). Тип сущности
  события и место для числа строк — Q-16.

## 5. Нефункциональные требования
- **NFR-1 (производительность):** `GET /me/overview`, `GET /me/overview/tasks` и `GET /me/overview/tasks.csv`
  — p95 ≤ 500 мс на 50 000 задач, стенд 3 vCPU / 6 ГБ (R2 NFR-09). Замер — в T-10 (спека 016).
  Для CSV учитывается лимит строк (Q-15).
- **NFR-2 (изоляция):** каждый запрос фильтруется по `workspace_id` актора и членству.
- **NFR-3 (интерфейс):** строки — в `ru.ts`; клавиатура; пресеты — `aria-pressed`; контраст WCAG AA;
  360 px без горизонтальной прокрутки (макет).
- **NFR-4 (без внешних вызовов):** новых исходящих запросов нет. Облачный шлюз (ADR-0022) на эту спеку
  не влияет: трекер ничего не вызывает ради шлюза.

## 6. Критерии приёмки
- **AC-1** (FR-2): Given участник двух проектов с задачами 2 `todo`, 1 `in_progress`, 1 `review`,
  1 `done` When `GET /me/overview` Then счётчики 2/1/1/1, «Всего» 5.
- **AC-2** (FR-2, видимость): Given задачи в проекте, где пользователь не участник, в удалённом проекте,
  мягко удалённые и в другом пространстве When `GET /me/overview` Then они не посчитаны.
- **AC-3** (FR-3): Given задачи в `review`: (а) я автор, (б) я владелец проекта, (в) я только
  участник-исполнитель When `GET /me/overview` Then «Нужно проверить» = 2.
- **AC-4** (FR-4, FR-6): Given фильтр `needs_review=true` When `GET /me/overview/tasks` Then в списке
  ровно задачи (а) и (б) из AC-3.
- **AC-5** (FR-6): Given задачи всех приоритетов When `priority=low&priority=high` Then в списке нет `medium`.
- **AC-6** (FR-7, граница суток): Given часы 2026-11-09T20:59:59Z (23:59:59 МСК) и 21:00:00Z (00:00 МСК
  10.11) When пресет «Сегодня» Then в первом случае — задачи со сроком 09.11, во втором — 10.11.
- **AC-7** (FR-7): Given сегодня 2026-11-08 (воскресенье); задачи со сроком 07.11, 08.11, 09.11, 16.11 и
  без срока When каждый пресет Then: «Просрочено» — 07.11; «Сегодня» — 08.11; «Завтра» — 09.11;
  «На этой неделе» — только 08.11 (прошедшие дни и 09.11 не входят, Q-4); «Без срока» — задача без срока.
  Отдельный кейс: сегодня понедельник — «На этой неделе» включает воскресенье той же недели.
- **AC-8** (FR-8): Given `high`+срок вчера, `high`+сегодня, `high`+завтра, `medium`+вчера, `high`+вчера в
  статусе `done` When список Then `hot=true` только у первых двух.
- **AC-9** (FR-9): Given 7 задач под фильтром и `page_size=5` When страница 1 Then `total=7`, 5 строк.
- **AC-10** (FR-11): Given ТА When запросы сводки Then 403; без сессии — 401; `project_id` чужого
  проекта — 404.
- **AC-11** (FR-6, валидация): Given `priority=urgent` или `due=someday` When запрос Then 422.
- **AC-12** (FR-10, FR-1): Given пользователь без задач When открыт `/summary` Then плитки с нулями и
  утверждённый текст пустого состояния; пункт «Сводка» в меню есть у БА и пользователя, нет у ТА.
- **AC-13** (FR-4, UI): Given экран When нажата плитка «В работе» Then фильтр статуса = «В работе» и
  список обновился.
- **AC-14** (NFR-1): p95 ≤ 500 мс на 50 000 задач для списка и CSV — проверяется в спеке 016 (T-10), вне CI.
- **AC-15** (FR-7, диапазон): Given задачи со сроками 09.11, 10.11, 12.11, 13.11 When `due_from=2026-11-10&due_to=2026-11-12`
  Then в списке 10.11 и 12.11 (границы включительно). When `due_from=2026-11-12&due_to=2026-11-10` Then 422.
- **AC-16** (FR-13, права CSV): Given БА When `GET /me/overview/tasks.csv` Then 200 и
  `Content-Type: text/csv; charset=utf-8`. Given пользователь (П) или ТА Then 403. Без сессии — 401.
- **AC-17** (FR-13, формат): Given выборка с кириллицей и кавычками в названии When CSV Then первые три байта —
  BOM (`EF BB BF`), разделитель `;`, первая строка — колонки из FR-13; файл читается CSV-читателем с
  разделителем `;` без потери символов.
- **AC-18** (FR-13, состав): Given 5 задач `high` и 2 задачи `medium`, фильтр `priority=high` When CSV Then
  5 строк данных и заголовок; число строк не зависит от `page_size`.
- **AC-19** (FR-14, аудит): Given успешная выгрузка БА When журнал аудита Then есть событие с автором,
  временем и числом строк; значений полей задач в событии нет.
