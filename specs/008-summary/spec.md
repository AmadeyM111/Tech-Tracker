# Spec: «Сводка» — плитки, «Нужно проверить», фильтры по приоритету и сроку, метка «Горит»

- **ID:** 008-summary
- **Статус:** DRAFT (вопросы §8 открыты)
- **Дата:** 2026-11-08
- **Пакет:** R2 T-03 (без CSV). Основание: решения владельца 2026-11-08; `r2-tz-amendments.md`
  (R2-1a…R2-1d); макет `Shared/Design/summary-r2-design.md` (утверждён); ADR-0007, ADR-0012, ADR-0013.

## 1. Контекст и цель
В R1 нет общего списка задач по всем проектам и фильтра по сроку (001/FR-27a отложен, ADR-0012).
Участник пилота должен одним экраном видеть, сколько задач в каждом статусе, что ждёт его проверки,
что просрочено и что горит. Экран «Сводка» закрывает 001/FR-27a и R2-1a…R2-1d. CSV, диапазон дат,
карточка «Подключить ИИ-агента», фильтр по исполнителю и метки в пакет не входят (R3).

## 2. Пользовательские сценарии
- Как участник, я хочу видеть число задач по статусам во всех моих проектах, чтобы понимать объём работы.
- Как автор задачи или владелец проекта, я хочу видеть задачи, которые ждут моей проверки.
- Как участник, я хочу отфильтровать задачи по проекту, статусу, приоритету и сроку, чтобы найти горящее.
- Как техадминистратор, я не вижу «Сводку»: бизнес-данные мне недоступны (ADR-0013).

## 3. Термины
- **Мои проекты** — неудалённые проекты пространства, где пользователь владелец или участник
  (`project.owner_id` или строка `project_member`), как у `can_read_project_content`.
- **Задачи сводки** — неудалённые задачи и подзадачи моих проектов (подзадачи наравне, 001/OI-23; см. Q-1).
- **Сегодня** — `today_msk()` (ADR-0007). Срок хранится как дата `YYYY-MM-DD`.

## 4. Функциональные требования
- **FR-1:** Система ДОЛЖНА показывать пункт «Сводка» в боковом меню пользователям с `business_access`
  и экран `/summary`.
- **FR-2 (плитки, R2-1a):** Экран ДОЛЖЕН показывать плитки «Всего», «Не начато» (`todo`), «В работе»
  (`in_progress`), «На проверке» (`review`), «Готово» (`done`) с числом задач сводки. Сумма четырёх
  статусов ДОЛЖНА равняться «Всего».
- **FR-3 («Нужно проверить», R2-1b):** Экран ДОЛЖЕН показывать отдельную плитку «Нужно проверить»:
  задачи сводки в `review`, где пользователь автор задачи (`created_by`) или владелец проекта.
- **FR-4 (переход по плитке):** Нажатие на плитку статуса ДОЛЖНО открывать список с фильтром этого
  статуса; «Всего» — без фильтра статуса; «Нужно проверить» — с фильтром «нужно проверить».
- **FR-5 (список):** Экран ДОЛЖЕН показывать постраничный список задач сводки с колонками «Проект»,
  «Задача», «Статус», «Приоритет», «Исполнитель», «Срок»; строка открывает карточку задачи.
  Порядок — по сроку по возрастанию, без срока в конце, тай-брейкер — `id` (см. Q-6).
- **FR-6 (фильтры):** Список ДОЛЖЕН фильтроваться по проекту (один из моих проектов), статусу,
  приоритету `low`/`medium`/`high` (мультивыбор, R2-1c) и сроку (FR-7). Фильтры объединяются через «И».
- **FR-7 (срок, R2-1d, 001/FR-27a):** Пресеты срока по Europe/Moscow:
  - «Просрочено» — `due_date < сегодня`;
  - «Сегодня» — `due_date = сегодня`;
  - «Завтра» — `due_date = сегодня + 1`;
  - «На этой неделе» — `due_date` в календарной неделе (пн–вс), содержащей сегодня;
  - «Без срока» — `due_date IS NULL`.
  Включение задач в `done` в «Просрочено» и «На этой неделе» — Q-3, Q-4.
- **FR-8 («Горит»):** Строка списка ДОЛЖНА нести метку «Горит», если приоритет `high` и
  `due_date <= сегодня` (см. Q-3 про `done`). Метка — текст, не только цвет.
- **FR-9 (количество):** Над списком ДОЛЖНА быть строка «Показано N из M», где M — число задач
  под текущими фильтрами (см. Q-5 про N).
- **FR-10 (пусто):** Если задач сводки нет, вместо списка ДОЛЖЕН показываться текст «Задач пока нет.
  Они появятся, когда вас добавят в проект или вы создадите задачу.»; плитки остаются с нулями.
- **FR-11 (права):** API сводки ДОЛЖНО отвечать 403 пользователю без `business_access` (ТА) и 401
  без сессии. Фильтр по чужому проекту (не мой, удалённый, другого пространства) ДОЛЖЕН давать 404
  (тот же ответ, что у проекта, которого нет).
- **FR-12 (обновление):** Плитки и список ДОЛЖНЫ обновляться опросом раз в 15 с (`POLL_INTERVAL_MS`).

## 5. Нефункциональные требования
- **NFR-1 (производительность):** `GET /me/overview` и `GET /me/overview/tasks` — p95 ≤ 500 мс на
  50 000 задач, стенд 3 vCPU / 6 ГБ (R2 NFR-09). Замер — в T-10 (спека 016).
- **NFR-2 (изоляция):** каждый запрос фильтруется по `workspace_id` актора и членству.
- **NFR-3 (интерфейс):** строки — в `ru.ts`; клавиатура; пресеты — `aria-pressed`; контраст WCAG AA;
  360 px без горизонтальной прокрутки (макет).
- **NFR-4 (без внешних вызовов):** новых исходящих запросов нет.

## 6. Критерии приёмки
- **AC-1** (FR-2): Given участник двух проектов с задачами 2 `todo`, 1 `in_progress`, 1 `review`,
  1 `done` When `GET /me/overview` Then счётчики 2/1/1/1, «Всего» 5.
- **AC-2** (FR-2, видимость): Given задачи в проекте, где пользователь не участник, в удалённом проекте,
  мягко удалённые и в другом пространстве When `GET /me/overview` Then они не посчитаны.
- **AC-3** (FR-3): Given задачи в `review`: (а) я автор, (б) я владелец проекта, (в) я только
  участник-исполнитель When `GET /me/overview` Then «Нужно проверить» = 2.
- **AC-4** (FR-4, FR-6): Given фильтр `needs_review=true` When `GET /me/overview/tasks` Then в списке
  ровно задачи (а) и (б) из AC-3.
- **AC-5** (FR-6): Given задачи всех приоритетов When `priority=low&priority=high` Then в списке нет `medium`.
- **AC-6** (FR-7, граница суток): Given часы 2026-11-09T20:59:59Z (23:59:59 МСК) и 21:00:00Z (00:00 МСК
  10.11) When пресет «Сегодня» Then в первом случае — задачи со сроком 09.11, во втором — 10.11.
- **AC-7** (FR-7): Given срок вчера, сегодня, завтра, в воскресенье этой недели, в понедельник
  следующей, без срока When каждый пресет Then каждый возвращает ожидаемый набор (таблица в тесте).
- **AC-8** (FR-8): Given `high`+срок вчера, `high`+сегодня, `high`+завтра, `medium`+вчера When список
  Then `hot=true` только у первых двух.
- **AC-9** (FR-9): Given 7 задач под фильтром и `page_size=5` When страница 1 Then `total=7`, 5 строк.
- **AC-10** (FR-11): Given ТА When запросы сводки Then 403; без сессии — 401; `project_id` чужого
  проекта — 404.
- **AC-11** (FR-6, валидация): Given `priority=urgent` или `due=someday` When запрос Then 422.
- **AC-12** (FR-10, FR-1): Given пользователь без задач When открыт `/summary` Then плитки с нулями и
  утверждённый текст пустого состояния; пункт «Сводка» в меню есть у БА и пользователя, нет у ТА.
- **AC-13** (FR-4, UI): Given экран When нажата плитка «В работе» Then фильтр статуса = «В работе» и
  список обновился.
- **AC-14** (NFR-1): p95 ≤ 500 мс на 50 000 задач — проверяется в спеке 016 (T-10), вне CI.

## 7. Вне рамок
CSV и аудит выгрузки; диапазон дат; фильтр по исполнителю; метки; поиск; карточка ИИ-агента;
настраиваемый часовой пояс; поле «проверяющий»; сохранение фильтров между сеансами.
