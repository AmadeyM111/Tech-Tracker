# 007: открытые вопросы и принятые риски для финальной приёмки (ведёт оркестратор)

Обновляется по мере ревью. В R7-T26 каждый пункт должен получить решение: исправлено / принято владельцем / перенесено.

1. **Откат часов назад в окне лимита** (R7-T11, `api_keys/auth.py:66-68,99`): при `rate_window_start > now` окно не сбрасывается, `retry_after` > 60 (проба: 3660 с). Обхода лимита нет, лишний отказ. Решение за архитектором/владельцем: считать окно новым при `rate_window_start > now` либо ограничить `retry_after` сверху 60.
2. **Лимит раньше состояния учётной записи** (R7-T12, plan §4.7): заблокированный/вне пространства агент с неотозванным ключом получает 401 на первые 120 запросов и 429 на 121-й; `last_used_at` обновляется у отказанных. Недостижимо через API. Принять как RK в plan или добавить `EXISTS` в `WHERE` UPDATE.
3. **Битый JSON на маршруте вне перечня по ключу → 400 вместо 403** (R7-T12): FastAPI разбирает тело раньше зависимостей; данные не меняются. Поправить текст plan §4.7 или принять.
4. **AC-47 и `test_logging.py`** (R7-T12): изменение существующего теста вынуждено FR-17; внести в трассировку AC-47 как обоснованное исключение, при необходимости подтвердить у владельца.
5. **Разбор схемы Bearer** (R7-T12, `deps.py:93`): `split()` принимает табуляцию/`\xa0`; безопасно, но строже по RFC 6750 — косметика.
6. **`generate_password()` вместо `secrets.token_urlsafe(32)`** (R7-T07, PD-4): выровнять plan или сервис.
7. **`/me` по ключу возвращает `capabilities` роли** (R7-T12 → R7-T13/R7-T18/З-6): возможности управления проектами у `agent.ba` показываются, хотя по ключу закрыты; инструменты MCP на них не опираются.
8. **Проверка `Retry-After` из очень длинной строки в MCP** (R7-T17 → R7-T18), лимит длины stdin — см. заметки R7-T18.
9. **`list_projects` не учитывает владельца без строки членства** (R7-T13, `projects/queries.py:180`): сужение доступа для запросов по ключу, через API недостижимо; для единообразия добавить `or_(Project.owner_id == actor.user_id, …)`.
10. **Решение по п.7** (`/me` по ключу и `capabilities`): фильтровать до реально доступных операций по ключу или принять как есть — решение владельца в R7-T26.
11. **Порядок проверок в `move`** (R7-T14, `tasks/service.py:520`): блокировки теперь берутся до проверки одинаковых соседей; при параллельном удалении 404/503 вместо 422; по PD-23. Принять или проверять соседей до блокировки.
12. **Нет теста гонки на «было» для событий** (R7-T14): мутации «снимок до блокировки» выживают; конкурентный тест в R7-T15/R7-T16.
13. **Рост `domain_event` без очистки** (R7-T14): append-only таблица растёт линейно от всех правок задач/комментариев; отметить в документации/эксплуатации (R7-T24).
14. **Усиление тестов R7-T15** (необязательно): конкурентный PATCH приоритета/исполнителя/срока/статуса подзадачи; `clock.advance` перед отказом в AC-28/AC-31; убрать недостижимую ветку в конкурентном тесте; латинские id параметров (`reviews/R7-T15-1.md`).
15. **Журнал web (nginx) и ключ в пути/строке запроса** (R7-T16, отчёт test-writer; вне описания задачи, нужно решение владельца): (a) `$uri` в `log_format gt_access` пишет путь без маскировки — ключ, ошибочно подставленный клиентом в путь, попадёт в access-лог web (вариант: `map $uri` с regex-маскированием); (b) сервер 80 (переадресация) пишет лог в формате `main` с `$request` — ключ в `?…` по HTTP попадёт в лог; (c) `error_log` nginx при ошибках апстрима (502/504) пишет `request: "GET …?query"`, `log_format` на него не действует. Настоящий ключ клиент передаёт только в заголовке `Authorization` (MCP), поэтому риск — при ошибке клиента; принять как RK или закрыть. (d) `$remote_user` (заполняется из `Authorization: Basic` даже без `auth_basic`, `curl -u gtk_…:` писал бы ключ целиком): **закрыто** — в `gt_access` заменён литералом `-` (ревью R7-T16, plan PD-11 п. 5). (e) `$uri` в фазе log берётся после внутреннего редиректа — SPA-маршруты пишутся как `/index.html` (наблюдаемость, не безопасность); `nginx -t` на стенде — ручная проверка R7-T24. Остаточный риск маскирования в логах приложения (порча ключа исключённым символом шаблона на позициях 4–38: открытой может остаться голова до 11 символов или хвост без префикса; порча префикса) — принят, plan §4.2.
16. **Заметка R7-T12 (nginx передаёт `Authorization` без искажений)** покрыта только статически (`/api/` не переписывает и не убирает заголовок); проверка на стенде требует Docker — на ручную проверку владельцу (R7-T24 чек-лист).
17. **Процесс:** test-writer R7-T16 однократно запустил `pytest -m infra_stack…` без `-k`, из-за чего выполнились Docker-тесты T27; их фикстура удалила собственные образ/контейнер/том `gt-t27-*`; тома стека (`pgdata`, `appdata`, `gostracker-web_*`) не затронуты. Дальнейшие прогоны — только с `-k`.
