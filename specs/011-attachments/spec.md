# Spec: Вложения к задачам

- **ID:** 011-attachments
- **Статус:** DRAFT (вопросы §8 открыты)
- **Дата:** 2026-11-08
- **Пакет:** R2 T-04 (R2-4…R2-8, R2-40, R2-41). Решения владельца 2026-11-08 (D-6): PDF, DOCX, XLSX,
  PPTX, TXT, CSV, PNG, JPEG, GIF, WebP, до 10 МБ; запрещены docm/xlsm/pptm, исполняемые и скрипты;
  SVG/HTML — только скачивание; антивируса нет. Зависит от 009 (файлы входят в копию).

## 1. Контекст и цель
Задача без файла неполна: техзадания, сметы, скриншоты пилотная команда пересылает в почте. В R1
вложений нет, хотя в конфиге есть лимиты, а в журнале — события `attachment.*`. Пакет даёт загрузку,
скачивание и удаление файлов в карточке задачи с безопасной отдачей и учётом в экспорте и копии.

## 2. Пользовательские сценарии
- Как участник проекта, я прикладываю PDF и скриншот к задаче и вижу файлы в карточке.
- Как участник, я скачиваю файл; картинку открываю в браузере.
- Как автор вложения или тот, кто может править задачу, я удаляю файл.
- Как ИБ, я уверен, что макросы, исполняемые файлы и скрипты не принимаются, а HTML/SVG не исполняются в браузере.

## 3. Функциональные требования
- **FR-1 (загрузка, R2-4):** участник проекта (`can_read_project_content`) ДОЛЖЕН мочь прикрепить файл к
  неудалённой задаче своего проекта. Остальным — 403 (ТА, не участник) или 404 (задачи нет).
- **FR-2 (размер, R2-5):** файл до `ATTACHMENT_MAX_BYTES` (10 485 760 байт) включительно ДОЛЖЕН
  приниматься, на байт больше — 413 `attachment_too_large`; пустой файл — 422. Лимит проверяют API и nginx.
- **FR-3 (количество):** не больше `ATTACHMENTS_PER_TASK` (20) неудалённых вложений на задачу, иначе 409 `too_many_attachments`.
- **FR-4 (типы, D-6):** тип определяется по расширению И сигнатуре содержимого; принимаются только
  PDF, DOCX, XLSX, PPTX, TXT, CSV, PNG, JPEG, GIF, WebP. Отклоняются (422 `attachment_type_not_allowed`):
  расширение не из списка; несовпадение расширения и сигнатуры; OOXML с макросами (`vbaProject.bin`,
  типы `macroEnabled`); TXT/CSV с нулевыми байтами или не в UTF-8.
- **FR-5 (хранение, R2-5):** файл ДОЛЖЕН лежать в `DATA_DIR/attachments/` под случайным ключом; в БД —
  исходное имя (только метаданные, очищенное от путей и управляющих символов, ≤ 255 символов), размер,
  тип, sha256, ключ хранения, автор, задача, проект, время. Имя файла в путь не попадает.
- **FR-6 (отдача, R2-6):** скачивание — после проверки прав (как FR-1), с заголовками
  `X-Content-Type-Options: nosniff`, `Content-Security-Policy: sandbox; default-src 'none'`,
  `Content-Disposition: attachment` (имя по RFC 6266/5987). `inline` — только PNG, JPEG, GIF, WebP.
- **FR-7 (удаление, R2-4, R2-7):** удалить вложение может его автор или тот, у кого
  `can_edit_task_fully`; удаление мягкое (`deleted_at`), файл удаляется окончательно `gtrack maintenance`
  через `TRASH_RETENTION` (30 дней, ADR-0010). Удалённое не отдаётся (404).
- **FR-8 (события):** загрузка и удаление ДОЛЖНЫ писать `attachment.created` / `attachment.deleted` в
  ленту проекта (имя файла — как у названий: по правилам ленты ADR-0015; в аудите ТА — только метаданные).
- **FR-9 (список):** карточка задачи ДОЛЖНА показывать неудалённые вложения: имя, размер, автор, время,
  ссылка скачать, кнопка «Удалить» по правам.
- **FR-10 (диск, R2-40):** если свободного места в `DATA_DIR` меньше `ATTACHMENTS_MIN_FREE_MB`, загрузка
  ДОЛЖНА отклоняться 507 `storage_full`; прочая работа продолжается.
- **FR-11 (экспорт, R2-8):** `gtrack export` ДОЛЖЕН включать файлы неудалённых вложений (`files/<ключ>`)
  и проверять sha256 при импорте; круг «экспорт → импорт → экспорт» сохраняет sha256.
- **FR-12 (копия):** вложения входят в `gtrack backup` (`appdata.tar`, spec 009) без изменений 009.

## 4. Нефункциональные требования
- **NFR-1:** файл пишется во временный файл в том же каталоге и публикуется атомарно; при ошибке
  временный файл удаляется; строка БД и файл согласованы (нет строки без файла).
- **NFR-2:** содержимое и имена файлов не пишутся в лог приложения (R2-44).
- **NFR-3:** загрузка 10 МБ не держит весь файл в памяти больше одного раза (потоковая запись с подсчётом).
- **NFR-4:** без внешних вызовов и антивируса (решение владельца; Q-6 ТЗ).

## 5. Критерии приёмки
- **AC-1** (FR-2): 10 485 760 байт PDF → 201; 10 485 761 → 413; 0 байт → 422.
- **AC-2** (FR-4): по одному файлу каждого разрешённого типа → 201; `.exe`, `.sh`, `.js`, `.html`, `.svg`,
  `.docm`, DOCX с `vbaProject.bin`, PNG с расширением `.pdf`, TXT с NUL → 422.
- **AC-3** (FR-1): ТА → 403; не участник → 403; чужое пространство или удалённая задача → 404; без сессии → 401.
- **AC-4** (FR-3): 21-й файл → 409.
- **AC-5** (FR-6): PNG отдаётся `inline`, PDF — `attachment`; во всех ответах `nosniff` и CSP `sandbox`;
  имя с кириллицей и кавычками корректно в `Content-Disposition`.
- **AC-6** (FR-5): имя `../../etc/passwd` сохраняется как `passwd`; путь на диске — случайный ключ в `attachments/`.
- **AC-7** (FR-7): автор удаляет своё → 204; пользователь удаляет чужое в чужой задаче → 403; БА-участник → 204;
  после удаления скачивание → 404; `maintenance` через 30 дней удаляет файл, раньше — нет.
- **AC-8** (FR-8): после загрузки и удаления в ленте проекта два события, в аудите ТА — без имени файла.
- **AC-9** (FR-10): свободное место ниже порога → 507, создание задачи работает.
- **AC-10** (FR-11): круг экспорта с файлами даёт тот же `data.json` и те же sha256.
- **AC-11** (FR-9): карточка показывает файл после загрузки; кнопка «Удалить» только по правам (vitest).

## 6. Вне рамок
Антивирус; предпросмотр PDF и Office; вложения к комментариям; перетаскивание нескольких файлов сразу;
квоты на проект; восстановление вложения из корзины (корзина — R3).

## 7. Допущения
- Загрузка — тело запроса целиком (`Content-Type` файла, имя — параметр `name`), без multipart:
  новой зависимости нет (plan).
- nginx уже ограничивает тело 12 МБ (`client_max_body_size 12m`).
